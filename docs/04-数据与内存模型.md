# 数据表示与内存模型

本文件固定节点的内部表示、输入所有权、分配器契约与失败清理规则。实现阶段不得在未修订本文件的情况下引入新分配路径。

## 1. 对象层次

| 对象 | 内部类型（计划） | 生命周期 | 持有内容 |
| --- | --- | --- | --- |
| 上下文 | `asnber::Context`（`src/core`） | 调用方创建/销毁 | 分配器、静态池、错误状态、资源上限、默认选项 |
| 文档 | `asnber::Document`（`src/types`） | 调用方创建/销毁 | 根节点、arena、节点计数、输入所有权、源编码规则 |
| 节点 | `asnber::Node`（`src/types`） | 随文档 | 标签元数据、内容切片、父子/兄弟链接、深度 |
| 模板 | `asnber::Schema`（`src/schema`） | 调用方创建/销毁，上下文级分配 | 类型树、约束、默认值 DER、模块默认标注方式 |
| 输出缓冲 | 上下文级缓冲记录 | `asnber_buf_release` 或上下文销毁 | 编码输出字节 |
| 值视图 | 按需生成的结构 | 随文档 | OID 点分文本、语义读取缓存等 |

公共头文件只暴露不透明句柄：

| C 句柄 | 内部实现 |
| --- | --- |
| `asnber_ctx_t` | `asnber::Context` |
| `asnber_doc_t` | `asnber::Document` |
| `asnber_node_t` | `asnber::Node` |

句柄转换只允许发生在 `src/c_api`；其他模块不得依赖 C 类型。

## 2. 节点表示

基线采用“**原始编码保留 + 只读语义视图**”的表示，不做模式驱动的值对象：

```text
Node
├─ tag_class            UNIVERSAL / APPLICATION / CONTEXT / PRIVATE
├─ tag_number           0 .. 2^32-1（高标签号已展开）
├─ flags                constructed / indefinite / has_children / ...
├─ depth                顶层为 0
├─ tlv_offset           在输入中的起始偏移
├─ tlv_size             完整 TLV 字节数（不定长时含 EOC）
├─ content              内容起始指针：解码文档指向输入切片，runtime 文档指向 arena；构造类型为 NULL
├─ content_size         内容字节数（不定长时为 0）
├─ parent               父节点指针；根为 NULL
├─ first_child          首个子节点；无子节点为 NULL
├─ last_child           末个子节点，用于 O(1) 追尾
├─ next_sibling         下一个兄弟；末尾为 NULL
├─ document             所属文档指针，用于 arena 归属与惰性缓存
└─ oid_text             OID 点分文本惰性缓存；未生成时为 NULL
```

设计约束：

1. **不急切解码值**。INTEGER、OID、字符串都以原始字节留在输入切片中，调用 `asnber_node_get_*` 时才解析；OID 的点分文本惰性生成并缓存在 arena 中。
2. **不复制结构**。节点之间用指针连接；父指针用于向上遍历，同时保证 C API 的 `asnber_node_parent` 为 O(1)。
3. **不丢弃未知信息**。原始 TLV 偏移与长度完整保留，支持 `asnber_node_tlv` 原样取回；即使启用模式校验，也不破坏编码级回读能力。
4. **构造节点无内容切片**。`SEQUENCE`、`SET`、显式标签等构造类型的 `content_size` 为 0，其内容由子节点表达；`asnber_node_content` 只对基本节点有效，构造节点返回 `ASNBER_E_INVALID_STATE`。
5. **兄弟链而非动态数组**。避免每个构造节点额外分配子数组；子节点按出现顺序串成单链，`asnber_node_child_at` 为 O(n)，文档建议频繁随机访问的调用方自行缓存。
6. **节点大小目标**：64 位宿主 ≤ 128 字节/节点（当前实现实测 96 字节）；32 位目标 ≤ 64 字节/节点，待实测固化。相对初版字段集，实现额外保留三个指针：`last_child`（O(1) 追加子节点）、`document`（arena 归属）与 `oid_text`（OID 惰性文本缓存）。若后续需要更紧凑的嵌入式表示，必须先补 ADR，不得在实现中临时压缩字段。

`Node` 不包含 `std::string`、`std::variant`、`std::vector` 等可能抛出或依赖 RTTI 的类型。

### 2.1 runtime 构树

- `asnber_doc_create` 创建空文档，节点从文档 arena 分配；追加子节点不移动已有节点。
- `asnber_node_create` 接受标签类别、标签号与构造位；根节点只能设置一次。
- `asnber_node_set_content/set_bool/set_int64/set_oid/set_utf8` 把内容复制到 arena，不借用调用方缓冲；同一节点只允许设置一次内容。
- `asnber_doc_seal` 冻结文档并校验结构；封存后文档与解码结果同等对待，节点只读。
- 失败时文档仍可销毁；不允许在封存后追加节点或修改内容。
- runtime 构树的节点不对应原始输入：`tlv_offset` 为 `SIZE_MAX`、`tlv_size` 为 0；`asnber_node_tlv` 返回 `NULL`/0，原始 TLV 回读只适用于解码文档。

## 3. 输入所有权

`asnber_decode_buffer` 默认**零拷贝借用**输入：

- `Document` 保存 `const uint8_t *` 与总长度，节点用偏移定位内容。
- 调用方必须保证输入内存在 `asnber_doc_destroy` 之前一直有效且内容不变。
- 适合较大输入、嵌入式常量表、已有大缓冲等场景。

可选策略：

| 场景 | 策略 | 行为 |
| --- | --- | --- |
| `asnber_decode_buffer` 默认 | 借用 | 不复制输入；文档销毁前输入必须有效 |
| `asnber_decode_buffer` + `ASNBER_DECODE_COPY_INPUT` | 复制 | 将输入复制到文档 arena，文档与调用方缓冲解耦 |
| `asnber_decode_reader` | 复制 | reader 数据按需读入 arena；不要求调用方长期持有任何缓冲 |

复制路径的内存会计入文档 arena 与输入字节预算；借用路径只按输入长度计入预算，不额外分配。无论哪种策略，文档销毁时都不释放调用方输入。

## 4. 分配器策略

### 4.1 上下文级与文档级两层分配

```text
调用方
  └─ asnber_allocator_t（可选自定义钩子）
       ├─ 上下文级分配（随 asnber_ctx_t 生命周期）
       │    ├─ 上下文对象与固定簿记
       │    ├─ schema 对象（asnber_schema_t）
       │    └─ 输出缓冲（asnber_buf_t）
       └─ 文档级 arena（随 asnber_doc_t 生命周期）
            ├─ 节点块
            ├─ 输入复制块
            └─ 惰性值视图
```

- **默认堆分配器**：未提供 `allocator` 时使用库内封装的 `malloc/realloc/free`。
- **自定义分配器钩子**：通过 `asnber_allocator_t` 注入，适合 RTOS、内存池、调试分配器。
- **可选静态池**：`asnber_ctx_config_t.static_pool + static_pool_size` 指定一段调用方持有的连续内存；上下文级分配与文档 arena 都只从该区域分配。
- 上下文级对象按对象申请/释放；文档 arena 只向底层分配器申请“块”，不逐节点申请，文档销毁时按块归还。schema 与输出缓冲不属于文档 arena，不随文档销毁。

### 4.2 分配器契约

| 项 | 约定 |
| --- | --- |
| `alloc(user, size)` | `size > 0`；返回 `max_align_t` 对齐的地址；失败返回 `NULL`，不得抛出异常 |
| `realloc(user, ptr, size)` | 允许为 `NULL`；为空时库用 `alloc + memcpy + free` 模拟；失败时原块保持有效 |
| `free(user, ptr)` | `ptr == NULL` 时为空操作；只释放本分配器返回的块 |
| 对齐 | 至少满足 `max_align_t`；库内部不依赖更大对齐 |
| 线程 | 回调可能被多个上下文共享；是否加锁由调用方决定，库不额外加锁 |
| 静态池 | 起始地址与大小必须满足对齐要求；池的生命周期必须覆盖上下文；不得与堆混用 |

### 4.3 静态池模式

启用静态池后：

- **池内存包含上下文对象本身**：`asnber_ctx_t` 及其固定簿记从池内分配，不额外走堆。
- 池起始地址必须按 `max_align_t` 对齐，对齐不满足返回 `ASNBER_E_INVALID_ARG`；`static_pool_size` 必须不小于 `asnber_ctx_size_for_config()` 返回的最小尺寸，尺寸不足返回 `ASNBER_E_INVALID_CONFIG`；地址为空但尺寸非 0 时同样返回 `ASNBER_E_INVALID_CONFIG`。
- `asnber_ctx_size_for_config(config, out_size)` 是唯一的最小尺寸查询入口；它在不分配内存的前提下计算“上下文对象 + 对齐填充 + 固定簿记”的字节数，失败返回错误码（`ASNBER_E_INVALID_ARG` / `ASNBER_E_INVALID_CONFIG` / `ASNBER_E_MEMORY_LIMIT`）。
- 上下文对象、schema、输出缓冲与文档 arena 都只从池内分配；池耗尽返回 `ASNBER_E_STATIC_POOL_EXHAUSTED`，**绝不回退到堆**。
- 文档 arena 与上下文级块销毁只逻辑归还池内块，不调用 `free`；池由调用方在上下文销毁后自行复用或丢弃。
- 静态池与自定义 allocator 同时提供时，以静态池为准；allocator 不参与池内分配。为避免歧义，基线建议二者不要同时提供。
- 建议池大小按 `asnber_ctx_size_for_config()` 的结果 + “最大节点数 × 节点大小 + 输入副本 + 输出缓冲 + 10% 余量”估算；具体值由集成方按业务上限压测确定，库不提供自动扩容。

### 4.4 预算记账

- 节点预算只约束 DOM：每次节点创建或文档 arena 块申请前检查是否超过 `max_nodes` 推导出的节点预算、是否超过输入/输出字节上限。
- schema 对象与描述表加载不受 `max_nodes` 约束，只受 `max_input_bytes` 与分配器/静态池容量约束；不存在“记录→节点”换算系数。
- 节点计数在创建节点前递增；失败时不需要回滚计数，因为整个文档会被销毁。
- 所有加法/乘法先检查溢出；`size * sizeof(Node)` 溢出返回 `ASNBER_E_INTERNAL` 或 `ASNBER_E_NOMEM`，不得截断。
- 记账值属于上下文；不同文档串行解码时预算按文档重置，不跨文档累计（输入/输出字节按单次操作计算）。
- 告警记录数由 `max_warnings` 单独限制（默认 1024）；达到上限只停止追加记录，不影响解码流程与主错误码。

## 5. 所有权与释放规则

| 对象 | 谁分配 | 谁释放 | 规则 |
| --- | --- | --- | --- |
| 上下文 | 调用方触发，库内分配 | `asnber_ctx_destroy` | 必须最后销毁 |
| 文档 | 库内分配 | `asnber_doc_destroy` | 必须在上下文销毁前 |
| 节点 | 文档 arena | 随文档销毁 | 无单节点释放接口 |
| 节点内容指针 | 输入缓冲或文档 arena | 文档销毁时不释放借用输入 | 见第 3 节；`asnber_node_content` 仅基本节点有效 |
| OID 点分文本 | 文档 arena | 随文档销毁 | 借用，不单独释放 |
| 输出缓冲 `asnber_buf_t` | 上下文级分配 | `asnber_buf_release` | 返回 `asnber_err_t`；只能释放本上下文产生的缓冲，跨上下文返回 `ASNBER_E_INVALID_ARG`；未释放时由上下文销毁兜底回收 |
| `asnber_schema_t` | 上下文级分配 | `asnber_schema_destroy` | 必须先于上下文销毁；未释放时由上下文销毁兜底回收 |
| reader/writer 及其 `user` | 调用方 | 调用方 | 库只借用，不释放 |

禁止事项：

- 禁止对 `asnber_node_t*` 调用 `free` 或 `delete`。
- 禁止在文档销毁后继续使用节点、内容、OID 文本或 TLV 切片。
- 禁止把库返回的借用指针交给第三方长期持有。
- 禁止把 `asnber_buf_t` 的 `data` 直接 `free`；必须走 `asnber_buf_release`。
- 禁止跨上下文释放 schema 或输出缓冲。`asnber_buf_release(ctx, buf)` 跨上下文返回 `ASNBER_E_INVALID_ARG`；`asnber_schema_destroy(schema)` 不接受调用方上下文，始终通过 schema 记录的所属上下文释放，因此不存在调用方上下文不匹配的入口。

`asnber_ctx_destroy` 会回收仍被上下文持有但未显式释放的 schema 与输出缓冲；这是兜底行为，不改变“文档与 schema 必须先于上下文销毁”的契约。上下文的分配记录只服务于本上下文，不能跨上下文复用。

## 6. 失败路径与清理

解码遵循“全有或全无”：

1. 入口校验失败：不创建文档，输出置 `NULL`，写入错误上下文。
2. 解析中途失败：停止解析，销毁文档（释放 arena 全部块），输出置 `NULL`，返回错误码。
3. 错误上下文保留出错偏移、深度与消息；文档不对外可见，因此不存在“半棵树”。
4. 输入借用模式下失败：不触碰调用方缓冲；复制模式下释放副本随文档一起回收。
5. 上下文保持可复用：调用方 `asnber_ctx_clear_error` 后可继续下一次解码。

编码失败：

- 使用 `asnber_encode_buffer`：失败时输出缓冲被释放并置零，不返回部分字节。
- 使用 writer 回调：writer 必须“全写或返回错误”；库在第一个回调错误处停止，把回调码包装为 `ASNBER_E_IO_WRITE` 并记录到 `callback_code`。已写入外部 sink 的字节无法回滚，调用方负责清理 sink。
- 编码过程中的临时缓冲来自上下文级分配或文档 arena；失败后随操作结束回收。

## 7. 嵌入式与受限环境

- `ASNBER_FREESTANDING` 下不使用 `malloc`、`new`、异常、RTTI、标准 IO、线程与文件系统；必须提供自定义 allocator 或静态池。
- 不使用递归析构；文档销毁是线性遍历 arena 块释放，不依赖节点递归。
- 不依赖 C++ 全局构造/析构顺序；内部只允许常量初始化数据。
- 无堆场景的最小配置：静态池 + 关闭异常/RTTI + 限制 `max_nodes`/`max_depth`/输入字节。
- 32 位目标：所有偏移使用 `size_t`；跨 ABI 的字节上限使用 `uint64_t` 并在入口检查可表示性。
- 不支持内存碎片整理、垃圾回收或引用计数；所有权必须是树形且单向。
