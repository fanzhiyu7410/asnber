# 错误模型

## 1. 基本原则

1. 所有公开操作通过 `asnber_err_t` 返回结果；`ASNBER_OK == 0`，错误码为正整数。
2. C++ 异常不得跨越 ABI；库内部也不使用异常作为控制流。
3. 错误码稳定且可分类；错误消息用于人读，不用于程序判断。
4. 失败时输出参数保持为空或原值；不暴露半成品。
5. 错误记录不依赖动态分配，保证在 `ASNBER_E_NOMEM` 场景下仍可读取错误码与偏移。

## 2. 错误码分类

| 区间 | 分类 | 含义 | 典型处理 |
| --- | --- | --- | --- |
| `0` | 成功 | 操作完成 | — |
| `1000–1999` | 调用/配置错误 | 参数非法、配置不合法、状态不允许、能力不支持 | 修正调用方代码 |
| `2000–2999` | 内存错误 | 分配失败、预算不足、静态池耗尽 | 降低负载/扩大预算 |
| `3000–3999` | 解码/数据错误 | 输入截断、标签/长度非法、编码规则违规、尾随数据 | 拒绝输入或记录问题数据 |
| `4000–4999` | 编码/值错误 | 无法编码的目标、值越界、规范化失败 | 修正输入文档或能力范围 |
| `5000–5999` | 资源上限 | 深度、节点数、输入/输出字节超限 | 调整上限或拒绝输入 |
| `6000–6999` | IO/回调错误 | reader/writer 回调失败 | 检查外部数据源/sink |
| `7000–7999` | 模板/模式校验 | 描述表版本不支持、字段缺失、约束不满足、类型不匹配 | 修正描述表或输入 |
| `8000–8999` | 内部错误 | 不变量破坏、不可恢复状态 | 销毁上下文并上报缺陷 |

## 3. 基线错误码表

| 错误码 | 值 | 类别 | 说明 |
| --- | --- | --- | --- |
| `ASNBER_OK` | 0 | 成功 | 操作成功 |
| `ASNBER_E_INVALID_ARG` | 1001 | 调用 | 空指针、非法索引、非法枚举值 |
| `ASNBER_E_INVALID_CONFIG` | 1002 | 配置 | `struct_size` 错误、预留字段非零 |
| `ASNBER_E_INVALID_STATE` | 1003 | 状态 | 句柄生命周期错误、上下文已失效 |
| `ASNBER_E_UNSUPPORTED` | 1004 | 能力 | 编码规则/目标能力不在基线范围 |
| `ASNBER_E_VERSION_MISMATCH` | 1005 | 配置 | `asnber_version_check` 的主版本与运行时主版本不一致；次版本差异视为兼容 |
| `ASNBER_E_NOMEM` | 2001 | 内存 | 底层分配器返回失败 |
| `ASNBER_E_MEMORY_LIMIT` | 2002 | 内存 | 预算记账拒绝本次分配 |

| `ASNBER_E_RANGE` | 4003 | 值读取 | 语义值超出目标类型（如 INTEGER 超过 int64） |
| `ASNBER_E_CONVERSION` | 4004 | 值读取 | 字符串转 UTF-8 失败或字符集不在白名单 |
| `ASNBER_E_DEPTH_LIMIT` | 5001 | 资源 | 嵌套深度超过上限 |
| `ASNBER_E_NODE_LIMIT` | 5002 | 资源 | 节点数超过上限 |
| `ASNBER_E_INPUT_LIMIT` | 5003 | 资源 | 输入字节超过上限 |
| `ASNBER_E_OUTPUT_LIMIT` | 5004 | 资源 | 输出字节超过上限 |
| `ASNBER_E_IO_READ` | 6001 | IO | reader 回调返回失败 |
| `ASNBER_E_IO_WRITE` | 6002 | IO | writer 回调返回失败 |
| `ASNBER_E_SCHEMA_FORMAT` | 7001 | 模板 | 描述表格式版本或布局不受支持 |
| `ASNBER_E_SCHEMA_TYPE` | 7002 | 模板 | 类型描述非法或引用不完整 |
| `ASNBER_E_SCHEMA_FIELD` | 7003 | 模板 | 字段缺失、重复或顺序不符合类型定义 |
| `ASNBER_E_SCHEMA_CONSTRAINT` | 7004 | 模板 | 值未满足约束（大小、值域、可扩展标记） |
| `ASNBER_E_SCHEMA_DEFAULT` | 7005 | 模板 | 默认值不是可规范化的 DER TLV，或解析失败 |
| `ASNBER_E_INTERNAL` | 8001 | 内部 | 不变量破坏；上下文应销毁 |

错误码值一旦发布不得改变语义；新增错误码在同一区间内追加。错误码不使用负值，避免与常见 POSIX 约定混淆。

### 3.1 本轮实现边界补充

- `asnber_doc_seal`：根节点缺失、基本节点未设置内容、构造节点设置了内容 → `ASNBER_E_INVALID_STATE`；标签号/类别非法、EOC（UNIVERSAL 0）在 `asnber_node_create` 阶段 → `ASNBER_E_INVALID_ARG`。
- BER 已支持多字节 tag number 与不定长（含嵌套、EOC 终止、`tlv_size` 含 EOC）；DER 遇不定长或构造内容中的 EOC → `ASNBER_E_INDEFINITE_NOT_ALLOWED`；顶层裸 EOC（UNIVERSAL 0）在 BER/DER 下 → `ASNBER_E_MALFORMED_TAG`。
- 无 schema 的解码接口传入 `STRICT_SCHEMA` → `ASNBER_E_INVALID_ARG`；`WARN_UNKNOWN_FIELD` 在无 schema 时被忽略。
- 解码选项含未定义标志位、非零 `reserved` 字段或大于上下文默认值的 `max_depth` → `ASNBER_E_INVALID_CONFIG`；`encoding` 为 `ASNBER_ENCODING_NONE`、`ASNBER_ENCODING_CER` 或未知值 → `ASNBER_E_UNSUPPORTED_ENCODING`。
- 空句柄：返回指针的元数据访问器取默认值，`asnber_node_content` 与 `asnber_node_get_*` 返回 `ASNBER_E_INVALID_ARG`（取值见 [C API 规范 §6.6](02-C-API规范.md)）。
- 错误 `path` 使用上下文固定槽位，不经 arena；无 schema 时为 `NULL`（与 §4 一致）。

## 4. 错误上下文

```c
typedef struct asnber_error_info {
    size_t struct_size;
    asnber_err_t code;
    int32_t callback_code;
    const char *message;
    size_t offset;
    uint32_t depth;
    uint32_t reserved;
    const char *path;
} asnber_error_info_t;
```

| 字段 | 填充规则 |
| --- | --- |
| `code` | 最近一次失败的对外错误码；无错误时为 `ASNBER_OK` |
| `callback_code` | 仅当 `code` 为 `ASNBER_E_IO_READ` / `ASNBER_E_IO_WRITE` 时有效，保存回调原样返回的整数；其他场景为 0 |
| `message` | 静态表生成的英文短消息；不使用动态格式化，不随语言变化 |
| `offset` | 解码错误为输入字节偏移；编码错误为已成功输出字节数；无意义时 `SIZE_MAX` |
| `depth` | 解码/编码出错时的嵌套深度；无意义时 0 |
| `path` | schema 感知解码/校验的字段路径；无 schema 或无法定位时为 `NULL` |

约束：

- 消息与 `path` 为上下文借用或静态存储，生命周期到下一次修改错误的调用或上下文销毁。
- 错误状态本身固定大小存放，不通过 arena 分配；保证 OOM 时仍能 `asnber_ctx_get_error`。
- 回调失败必须包装：reader 返回非零 → `ASNBER_E_IO_READ`，writer 返回非零 → `ASNBER_E_IO_WRITE`；原始回调码只放 `callback_code`，不参与对外错误分类。
- `format_version` 与描述表布局问题统一映射为 `ASNBER_E_SCHEMA_FORMAT`；`struct_size` 错误仍为 `ASNBER_E_INVALID_CONFIG`。
- 错误消息语言固定为英文 ASCII；本地化不在基线内（见[未决问题](待确认问题.md)）。

## 5. 可恢复与致命

| 类型 | 示例 | 上下文状态 | 文档状态 | 调用方动作 |
| --- | --- | --- | --- | --- |
| 调用错误 | 空指针、非法枚举 | 不变 | 不创建 | 修正参数后重试 |
| 配置错误 | `struct_size` 错、预留字段非零 | 创建失败 | 无 | 修正配置 |
| 数据错误 | 截断、非法长度、尾随数据 | 记录错误，仍可用 | 不返回 | 清理后可继续 |
| 资源上限 | 深度/节点/字节超限 | 记录错误，仍可用 | 不返回 | 调整上限或拒绝输入 |
| IO 错误 | reader/writer 回调失败 | 记录错误，仍可用 | 解码不返回；编码已写出的字节无法回滚 | 检查外部源/sink，清理 sink |
| 内存错误 | `ASNBER_E_NOMEM` | 记录错误，仍可用（错误状态不分配内存） | 不返回 | 降低预算后重试 |
| 内部错误 | 不变量破坏、分配器契约违规 | 标记失效 | 不返回 | 销毁上下文，上报缺陷 |

“上下文仍可用”指可以调用 `asnber_ctx_clear_error` 后继续新的操作；不表示可以继续使用失败操作产生的任何输出。

writer 契约是“全写或返回错误”：回调返回 `ASNBER_OK` 表示本次 `size` 字节全部被接受；返回非零表示失败，库包装为 `ASNBER_E_IO_WRITE` 并立即中止。库不产生“成功但只写了一部分”的结果，也不回滚已写出的字节。

## 6. 内部错误传递

- 内部函数统一返回 `Status`（包含 `asnber_err_t` 与可选的细节字段），需要返回值的函数使用“状态 + 输出参数”形式，不引入异常或 `Result<T>` 变体。
- 禁止用 `errno` 作为内部错误通道；系统调用/标准库返回值必须映射到上表。
- 禁止在库内打印日志、写 `stderr` 或调用 `abort`；调试断言只在 `ASNBER_DEBUG` 构建启用，发布构建移除。
- 禁止吞掉错误后返回成功；所有失败必须传播到最近的可返回边界。
- 分配失败不得尝试分配错误消息；错误上下文使用固定槽位。

## 7. 调用方处理范式

```c
asnber_err_t rc = asnber_decode_buffer(ctx, data, size, &options, &doc, &consumed);

if (rc != ASNBER_OK) {
    asnber_error_info_t info;
    info.struct_size = sizeof(info);

    if (asnber_ctx_get_error(ctx, &info) == ASNBER_OK) {
        /* code 用于程序判断；message 仅用于日志 */
        log_error(info.code, info.callback_code, info.message,
                  info.offset, info.depth, info.path);
    }

    /* 失败时 doc 必须为 NULL；无需销毁 */
    return rc;
}
```

调用方不应：

- 依赖消息文本做分支判断；
- 在失败后继续使用输出句柄；
- 在上下文已返回 `ASNBER_E_INTERNAL` 后继续调用除 `asnber_ctx_destroy` 以外的接口。
