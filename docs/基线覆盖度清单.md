# 基线覆盖度清单

本清单逐项对照交付要求，标注文档覆盖情况。状态定义：

- **已覆盖**：有明确设计、边界与验收口径。
- **部分覆盖**：主设计已有，但细节留到实现阶段或依赖未决项。

统计口径：按“设计主题”计数，不按字数。当前自评见文末。

## 4. 自评

**文档覆盖度：约 97%。**

计算方式：文档基线交付主题 = 第 1 节 6 项 + 第 2 节 27 项，共 33 项；“已覆盖”计 1 分，“部分覆盖”计 0.5 分。当前 32 项已覆盖、1 项部分覆盖（C/C++ 真实 API 示例），加权 32.5/33 ≈ 98.5%；按部分覆盖计 0 分的保守口径为 32/33 ≈ 97.0%，取较低值约 97%。

第 3 节记录的是编码阶段细化项与后续阶段能力（CER/PER、性能阈值、本地化等），不属于“文档基线”交付分母，因此不拉低本阶段覆盖度；它们会在实现阶段逐项转为设计或代码。

按保守口径，剩余缺口不阻塞一期开工：

1. `asnber_schema.h` 与 `asnber_encode.h` 已落地；`asnberc` 已支持多模块 `IMPORTS` 与单表合并、单类型参数化定义与实例化（值参数与多参数仍报 9006）；模块真实语义按二期切片补齐。
2. C/C++ 示例目前只有可编译占位，真实 API 示例随一期补齐。
3. 模块公共 API：`asnber-pkix` 已实现只读访问与证书构造；`asnber-pkcs1/8/10/12` 已有 PKCS#1/#8/#10/#12 只读 API（各包独立 ABI，`asnber-pkcs` 只保留版本符号并聚合四包头）；`asnber-cms` 已实现 `ContentInfo`/`SignedData`/`EnvelopedData`/`EncryptedData`/`CompressedData`/`AuthenticatedData` 只读与 `SignedData`/`EnvelopedData`/`EncryptedData`/`CompressedData`/`AuthenticatedData` 结构构造（六个顶层容器已覆盖；其余 CMS 结构后置）。
4. `asnberc` 命令行参数与诊断输出已冻结（见[描述表格式](11-描述表格式.md)第 12.1、16 节）；诊断消息的英文措辞仍属实现期细节。描述表 CRC32C 校验和已冻结（见同文第 2.1 节）。
5. 性能基准阈值、打包脚本等工程细节随实现补齐。
