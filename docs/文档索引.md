# asnber 设计文档

本目录是 `asnber` 库的设计基线。实现状态、验证证据与已知限制以 [测试与验证](07-测试与验证.md) 为准。

项目采用“通用核心 + 独立标准模块”的分层：核心 `asnber` 不含任何领域知识，X.509/PKIX、CMS、PKCS 由 `asnber-pkix`、`asnber-cms`、`asnber-pkcs1/8/10/12`（`asnber-pkcs` 为门面）提供；`.asn1` 文本解析由独立工具 `asnberc` 完成。模块只依赖核心，核心不反向引用模块。

- 基线版本：文档基线 0.1（2026-11-03）
- 适用对象：库作者、集成方、评审人
- 单一设定原则：本目录只维护一套当前有效的设计，不使用编号式多版本并存设定；历史决策通过 ADR 记录，不通过并行文档记录。
- 决策状态：标记为“基线决策”的内容默认采纳；标记为“待确认”的内容必须在编码阶段前由项目负责人确认，汇总见 [未决问题清单](待确认问题.md)。

## 基线边界

当前基线明确覆盖：

- 对外只提供 C ABI；内部全部为 C++，公共头文件不泄漏任何 C++ 类型。
- 必备编码规则：BER 解码、DER 解码与 DER 编码；BER 编码以 DER 输出作为合法子集。
- 通用（无模板）解码：保留原始标签与未知节点，支持结构遍历、原始切片访问与常用语义读取。
- runtime C API 构树：创建文档、创建节点、设置内容、封存并编码，是无模板编码的主线路径。
- 核心模板机制：已编译描述表加载与运行时注册 API 指向同一类型树；类型种类/标注方式、结构化约束、规范 DER 默认值、扩展标记与告警。
- 描述表契约：`uint8_t[]` 显式小端布局、版本兼容、越界与恶意输入校验、`asnberc`/核心共享输出规则。
- `asnberc` 一期 MVP：解析 `.asn1` 文本（自包含展平模块或多模块 `IMPORTS`）、语义校验、生成描述表；支持单类型参数化定义与实例化（值参数与多参数仍报 9006）；诊断格式与错误码冻结。
- 增量 feed 解码：`asnber_decoder_create`/`feed`/`finalize` push 模式入口，与 `asnber_decode_buffer` 行为一致。
- `CLASS`/`WITH SYNTAX`/信息对象集：一期以预展开模块输入，原版保留作参考并做等价性校验。
- `asnber-pkix` 一期：RFC 5912 描述表与证书字段访问，作为模板机制的首个验证消费者。
- 内存、错误、资源上限、构建导出、测试策略、依赖许可、编码规范与分期验收标准。

当前基线明确不覆盖：

- 核心内置任何标准结构表或领域概念（X.509/PKIX/CMS/PKCS）。
- `asnber-pkcs1/8/10/12` 的密码学语义（解密、口令派生、RSA 运算与填充、验签、PKCS#12 MAC 校验）。
- `asnber-cms` 的其余结构与密码学语义（只读切片已落地 `ContentInfo`/`SignedData`/`EnvelopedData`/`EncryptedData`；PKCS#7 归入 CMS；PKIX 类型在 CMS 内复制）。
- 模板机制的跨模块增量校验与字段路径增强；`asnberc` 值参数化、多参数参数化与 `CLASS`/`WITH SYNTAX` 直接解析（单类型参数化已落地）。
- CER / PER / UPER 的实际实现（CER 需求触发；PER/UPER 暂不规划）。
- 合规认证、性能阈值与打包发布细节。

## 文档维护约定

1. 设计变更先改主文档，再补 ADR；ADR 只记录“为什么这样选”，不复制主文档细节。
2. 任何标记为“待确认”的决策在确认后必须同步更新：主文档、ADR 状态、[覆盖度清单](基线覆盖度清单.md)、[未决问题清单](待确认问题.md)。
3. 文档中的 API 签名是设计基线，实现阶段以公共头文件为准；若实现必须偏离基线，先提交 ADR 修订。
4. 术语以[术语表](10-术语表.md)为准，新增术语必须先登记。
5. Mermaid 图只表达层次与依赖，不堆叠装饰性箭头；层级已由分组表达时不再补连线。
