# 性能基线

本文件记录模块 `open + close` 的可复现基线，用于判断是否需要上下文级 schema 缓存、评估后续优化收益。它不是 SLA，也不构成“生产可用”结论。

## 1. 测量对象

`tests/bench/bench_module_open.c` 固定五组输入，全部来自 `tests/data/`：

| 组 | 输入 | 模块入口 |
| --- | --- | --- |
| `pkix_certificate` | `cert_rsa_selfsigned.der`（865 字节） | `asnber_pkix_certificate_open` |
| `pkcs8_private_key_info` | `key_rsa_pkcs8.der`（1,216 字节） | `asnber_pkcs_private_key_info_open` |
| `pkcs1_rsa_private_key` | `key_rsa_pkcs1_private.der`（1,190 字节） | `asnber_pkcs_rsa_private_key_open` |
| `pkcs10_certification_request` | `csr_rsa.der`（641 字节） | `asnber_pkcs_certification_request_open` |
| `cms_content_info` | `cms_rsa_attached.der`（1,596 字节） | `asnber_cms_content_info_open` |

每次迭代计时范围为一次 `open + close`。`open` 内部加载模块描述表、构建 schema 并严格解码 DER；`close` 销毁句柄与文档。模块没有全局 schema 缓存，因此该数字反映“每次调用都重建 schema”的当前策略。

## 2. 方法与口径

- 计时使用单调墙钟：Windows 为 `QueryPerformanceCounter`，POSIX 为 `CLOCK_MONOTONIC`。
- 每组先预热一次（不计入样本），再分别执行 1,000 与 10,000 次，逐次保存耗时。
- `min`/`median`/`p95` 由排序后的逐次样本计算；`p95` 采用最近秩 `ceil(0.95 × N)`；`mean` 为样本算术平均。
- 峰值内存使用计数分配器统计库通过上下文分配器申请的总字节数。`peak_heap_bytes` 含上下文自身基线（本机为 440 字节），`peak_delta_bytes` 为扣除基线后的增量；`live_after_close_delta` 应恒为 0。
- 每组使用独立上下文，结束后销毁；进程内不复用 schema。

## 3. 构建与运行

```bash
cmake -S . -B build-bench -G Ninja \
  -DCMAKE_BUILD_TYPE=Release \
  -DASNBER_BUILD_SHARED=OFF \
  -DASNBER_BUILD_STATIC=ON \
  -DASNBER_BUILD_MODULE_PKCS=ON \
  -DASNBER_BUILD_MODULE_CMS=ON \
  -DASNBER_BUILD_BENCHMARKS=ON \
  -DASNBER_BUILD_TESTS=OFF
cmake --build build-bench --target bench_module_open --parallel
./build-bench/tests/bench/bench_module_open
```

数据目录已由 CMake 注入为源码树 `tests/data` 的绝对路径；也可以在执行时传入第一个参数覆盖：

```bash
./build-bench/tests/bench/bench_module_open /path/to/data
```

共享库配置同样可构建该目标；当静态库可用时优先链接静态库，避免 Windows 运行期 DLL 搜索路径影响计时。

## 5. 解读与限制

- PKIX 证书打开明显高于其余组，主要成本是按 24 KB 量级 PKIX 描述表重建 schema；与输入 865 字节本身关系不大。若后续调用方需要高频打开证书，优先评估“上下文级 schema 缓存”，而不是优化单次解码。
- PKCS#8/PKCS#1/PKCS#10 的打开成本处于数十微秒量级；CMS `ContentInfo` 因载入 CMS 描述表与更大的样本，居于两者之间。
- `p95` 与 `min` 差距较大，主要来自 Windows 桌面调度、其他进程干扰与偶尔的页错误；该基线适合比较同一环境下的相对变化，不应作为硬实时指标。
- 本表只测 `open + close`，不含结构化字段访问、编码、密码学运算与网络/IO。
- 结果对 CPU、编译器、构建类型与链接形态敏感；跨平台比较必须固定这些条件并注明环境。
