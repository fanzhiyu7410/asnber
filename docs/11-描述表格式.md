# 描述表格式

本文件是 `asnberc` 与核心库之间的**唯一共享契约**：`asnberc` 生成描述表，核心通过 `asnber_schema_load` 读取描述表。任何一方修改布局都必须先修订本文件并提升 `format_version`。

描述表只描述**已编译的 ASN.1 类型系统**，不包含 `.asn1` 文本、注释、词法信息或代码生成模板。运行期不解析文本，也不依赖 C 编译器结构体布局。

## 1. 总体原则

1. **字节布局显式固定**：所有字段按固定偏移、固定宽度、固定端序读写，不映射为 C 结构体。
2. **单一端序**：文件内所有多字节整数使用**小端**。文件头带端序标记，读取方必须校验。
3. **偏移相对文件起点**：所有 `offset` 字段都是相对描述表首字节的绝对偏移，不是指针。
4. **只读输入**：核心加载时校验并复制需要的名称、约束与默认值；不修改调用方数据。
5. **可复现**：相同输入与相同 `asnberc` 版本必须生成逐字节相同的输出。
6. **无版本并存**：只维护一个 `format_version` 的当前格式；旧格式通过拒绝加载处理，不提供并行解析分支。

## 2. 文件头

文件头基线 **108 字节**（`header_size` 可大于基线，见下文扩展规则）：

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 8 | `magic` | 固定字节 `41 53 4E 31 53 43 48 1A`（ASCII `ASN1SCH` + `0x1A`） |
| 8 | 4 | `format_version` | `(1u << 16) \| 0`；按 `major << 16 \| minor` 解释，主版本必须为 1、次版本为 0 |
| 12 | 4 | `header_size` | 文件头字节数；必须 `>= 96` 且 `<= total_size`，基线为 108 |
| 16 | 4 | `endianness` | 固定值 `0x01020304`；按小端读取，若得到 `0x04030201` 说明端序错误 |
| 20 | 4 | `module_tag_mode` | 模块默认标注方式：0 = `AUTOMATIC`，1 = `EXPLICIT`，2 = `IMPLICIT`，3 = 未声明 |
| 24 | 4 | `flags` | 位 0 必须为 1（已启用校验和）；其余位必须为 0 |
| 28 | 4 | `checksum_alg` | 必须为 1（CRC32C）；其他值拒绝 |
| 32 | 8 | `total_size` | 整个描述表字节数；必须等于 `asnber_schema_table_t.size` |
| 40 | 4 | `string_pool_offset` | 字符串池起始偏移 |
| 44 | 4 | `string_pool_size` | 字符串池字节数 |
| 48 | 4 | `type_table_offset` | 类型表起始偏移 |
| 52 | 4 | `type_count` | 类型记录数 |
| 56 | 4 | `field_table_offset` | 字段表起始偏移 |
| 60 | 4 | `field_count` | 字段记录数 |
| 64 | 4 | `constraint_table_offset` | 约束表起始偏移 |
| 68 | 4 | `constraint_count` | 约束记录数 |
| 72 | 4 | `default_table_offset` | 默认值表起始偏移 |
| 76 | 4 | `default_count` | 默认值记录数 |
| 80 | 4 | `checksum` | CRC32C 校验和值；计算时本字段按 0 参与 |
| 84 | 4 | `reserved0` | 必须为 0 |
| 88 | 4 | `reserved1` | 必须为 0 |
| 92 | 4 | `reserved2` | 必须为 0 |
| 96 | 4 | `root_type_id` | 生成期默认根：0 = 无根（允许多个顶层类型并列）；非 0 必须指向存在的类型记录（`1..type_count`）。加载时可由 `asnber_schema_load_with_root` 覆盖，覆盖不改变表字节与校验和 |
| 100 | 4 | `name_table_offset` | 名称表起始偏移；`header_size >= 108` 时有效，`100 <= header_size < 108` 时不存在（视为 0） |
| 104 | 4 | `name_count` | 名称记录数；`header_size >= 108` 时有效，`100 <= header_size < 108` 时不存在（视为 0） |

规则：

- `header_size` 必须 `>= 96`；基线为 **108**。`header_size` 小于 96 或大于 `total_size` 返回 `ASNBER_E_SCHEMA_FORMAT`。
- 分档读取：`header_size >= 108` 时读取偏移 96/100/104 的 `root_type_id`、`name_table_offset` 与 `name_count`；`100 <= header_size < 108` 时读取 `root_type_id`，名称表字段不存在（`offset = 0`、`count = 0`）；`header_size < 100` 时 `root_type_id` 与名称表字段均视为 0（兼容 96 旧基线）。
- 名称表为空（`name_count = 0`）时 `name_table_offset` 可以为 0 或任意值，不产生语义；`name_count > 0` 时 `name_table_offset` 必须落在 `[header_size, total_size)` 且 `name_table_offset + name_count * 24 <= total_size`。记录布局与校验见第 17 节。
- `header_size` 超出 108 的尾部字节视为未知扩展字段并忽略，但必须落在 `total_size` 内；未知尾部不参与语义。
- 各表区间（字符串池、类型表、字段表、约束表、默认值表、名称表）必须落在 `[header_size, total_size)` 内、互不重叠；默认值数据不得与任何表区间重叠。允许表之间填充对齐字节，但填充字节不参与语义。
- `module_tag_mode` 记录源模块的 `DEFINITIONS ... TAGS`：`AUTOMATIC TAGS` → 0，`EXPLICIT TAGS` → 1，`IMPLICIT TAGS` → 2，未声明 → 3。
- 加载映射：0→`IMPLICIT`、1→`EXPLICIT`、2→`IMPLICIT`、3→`DEFAULT`。`AUTOMATIC` 的标签分配在生成期完成，核心只把 0 与 2 同等对待；头部原值保留用于溯源与诊断。
- 类型级 `tag_mode` 只有 `DEFAULT / EXPLICIT / IMPLICIT`；`DEFAULT` 表示继承头部 `module_tag_mode`（`AUTOMATIC` 按 `IMPLICIT` 继承）。
- `root_type_id` 非 0 且越界（大于 `type_count`）返回 `ASNBER_E_SCHEMA_FORMAT`；0 表示不做单一根约束。
- 头部 `root_type_id` 是**生成期默认根**。同一 `.asn1` 文件若包含多个顶层类型，生成器只写一个默认根，其余根由模块在调用 `asnber_schema_load_with_root` 时指定；该覆盖不写回表字节，CRC32C 仍按原表计算。
- `asnber_schema_table_t.format_version` 是调用方期望版本，必须与头部 `format_version` 完全相等；不等返回 `ASNBER_E_SCHEMA_FORMAT`。
- 所有表偏移建议按 8 字节对齐；对齐只是性能优化，读取方不得依赖对齐。

### 2.1 校验和

校验和已冻结为 **CRC32C（Castagnoli）**，以下参数为契约的一部分：

| 参数 | 值 |
| --- | --- |
| 多项式 | `0x1EDC6F41`（Castagnoli） |
| 初值 | `0xFFFFFFFF` |
| 输入反射 / 输出反射 | 是 / 是（refin = true、refout = true） |
| xorout | `0xFFFFFFFF` |
| 校验范围 | 整个描述表字节 `[0, total_size)`，**计算时 `checksum` 字段（偏移 80，4 字节）按 0 参与** |
| 字节序 | 结果按小端存放于 `checksum` |

规则：

- `flags` 位 0 必须为 1，`checksum_alg` 必须为 1；任一不满足返回 `ASNBER_E_SCHEMA_FORMAT`。
- `asnberc` 生成描述表时**必须**写入 CRC32C；核心加载时**必须**校验，不提供“跳过校验”的运行期开关或选项。
- 校验和不匹配返回 `ASNBER_E_SCHEMA_FORMAT`，不区分为“损坏”还是“算法不支持”。
- CRC32C 覆盖整个 `[0, total_size)`，表间填充字节也参与校验和；生成器必须把填充字节写成确定值（基线固定为 `0x00`），否则同一输入无法保证逐字节可复现。
- 基线不提供任何关闭校验的开关，包括 CMake 选项与运行期参数；若将来为本地调试引入编译期开关，必须非默认、不进入公共 ABI，并在构建文档中标注“关闭后加载未经校验的输入存在安全风险”，发布构建始终开启。

## 3. 字符串池

字符串池保存所有名称与十进制边界文本，布局为连续的 NUL 结尾字节序列。

| 规则 | 说明 |
| --- | --- |
| 首字节 | 固定为 `0x00`，作为“空引用”哨兵；有效字符串偏移从 1 开始 |
| 引用方式 | 表记录中的 `*_off` 字段为相对文件起点的绝对偏移；0 表示无字符串 |
| 终止 | 字符串以**首个 NUL** 终止，长度由该终止符决定；同一偏移必须总能解析出同一文本 |
| 内容 | ASCII 可打印字符；类型名/字段名符合 ASN.1 标识符规则；十进制边界只含可选 `-` 与 `0-9` |
| 重复 | 相同文本必须复用同一偏移，保证可复现与体积最小 |
| 编码 | 不做 Unicode 规范化；名称按源模块原样保存（ASN.1 标识符本身是 ASCII） |

越界、未终止或偏移指向首字节的引用均视为格式错误。字符串池条目不存在“内嵌 NUL”概念：首个 NUL 即终止符，其后的字节属于下一字符串或填充。

## 4. 类型表

类型表为定长记录数组，每条 **48 字节**：

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | `name_off` | 类型名在字符串池中的偏移；不得为 0 |
| 4 | 2 | `kind` | 0 = SIMPLE，1 = SEQUENCE，2 = SET，3 = CHOICE，4 = SEQUENCE_OF，5 = SET_OF，6 = ANY |
| 6 | 1 | `tag_mode` | 0 = DEFAULT，1 = EXPLICIT，2 = IMPLICIT |
| 7 | 1 | `flags` | 位 0 = `ASNBER_TYPE_EXTENSIBLE`；其余位必须为 0 |
| 8 | 1 | `tag_class` | 0 = UNIVERSAL，1 = APPLICATION，2 = CONTEXT，3 = PRIVATE |
| 9 | 1 | `reserved0` | 必须为 0 |
| 10 | 2 | `reserved1` | 必须为 0 |
| 12 | 4 | `tag_number` | 有效标签号；`CHOICE` 在 `tag_mode = DEFAULT/IMPLICIT` 时必须为 0，`EXPLICIT` 时为外层包装标签号 |
| 16 | 4 | `element_type_id` | 仅 SEQUENCE_OF/SET_OF 使用；其他必须为 0 |
| 20 | 4 | `field_start` | 该类型字段在字段表中的起始下标 |
| 24 | 4 | `field_count` | 字段数量 |
| 28 | 4 | `constraint_start` | 该类型约束在约束表中的起始下标 |
| 32 | 4 | `constraint_count` | 类型级约束数量 |
| 36 | 4 | `reserved2` | 必须为 0 |
| 40 | 4 | `reserved3` | 必须为 0 |
| 44 | 4 | `reserved4` | 必须为 0 |

类型语义：

| `kind` | 含义 | 构造性 | 标签规则 |
| --- | --- | --- | --- |
| `SIMPLE` | 单一基本类型，内容按通用标签解释 | 非构造 | 必须给出有效 `tag_class/tag_number`：`UNIVERSAL` 下 `tag_number` 必须大于 0；`CONTEXT/APPLICATION/PRIVATE` 下 `tag_number = 0` 合法；`IMPLICIT` 仅对非 UNIVERSAL 标签有意义 |
| `SEQUENCE` | 有序字段集合 | 构造 | `tag_class = UNIVERSAL && tag_number = 0` 表示默认 UNIVERSAL 16 |
| `SET` | 无序字段集合 | 构造 | `tag_class = UNIVERSAL && tag_number = 0` 表示默认 UNIVERSAL 17 |
| `CHOICE` | 备选分支集合 | 由选中分支决定 | `DEFAULT`：无自身标签，必须 `tag_class = UNIVERSAL`、`tag_number = 0`；`EXPLICIT`：可带非 UNIVERSAL 的 `tag_class/tag_number` 作为外层显式包装；`IMPLICIT` 非法 |
| `SEQUENCE_OF` | 元素有序集合，元素类型由 `element_type_id` 指定（可为 ANY） | 构造 | `tag_class = UNIVERSAL && tag_number = 0` 表示默认 UNIVERSAL 16；`element_type_id` 必填 |
| `SET_OF` | 元素无序集合，元素类型由 `element_type_id` 指定（可为 ANY） | 构造 | `tag_class = UNIVERSAL && tag_number = 0` 表示默认 UNIVERSAL 17；`element_type_id` 必填 |
| `ANY` | 开放类型，保留完整原始 TLV | 由 schema 决定 | 无包装：`tag_class = UNIVERSAL`、`tag_number = 0`、`tag_mode = DEFAULT`（不应用模块默认标注）；外层包装：`tag_mode = EXPLICIT` + 非 UNIVERSAL 的 `tag_class/tag_number`；`element_type_id = 0`；`field_count = 0`；`constraint_count = 0` |

`kind` 与 `tag_mode` 的冲突判定：

- `CHOICE` + `IMPLICIT`：非法，返回 `ASNBER_E_SCHEMA_TYPE`。
- `CHOICE` + `DEFAULT`：必须 `tag_class = UNIVERSAL`、`tag_number = 0`，表示无自身标签；即使模块默认标注为 `IMPLICIT`，也不把隐式标签应用到 `CHOICE` 类型本身；否则非法。
- `CHOICE` + `EXPLICIT`：允许带非 UNIVERSAL 的 `tag_class/tag_number` 作为外层显式包装；`tag_class = UNIVERSAL` 或缺少有效外层标签时非法。
- `tag_class = UNIVERSAL` 且 `tag_mode != DEFAULT`：非法（通用标签不参与显式/隐式覆盖）。
- `SIMPLE` + `IMPLICIT` 且 `tag_class = UNIVERSAL`、`tag_number = 0`：非法。`CONTEXT/APPLICATION/PRIVATE` 下 `tag_number = 0` 合法，例如 PKIX 中的 `[0] IMPLICIT`；`0` 只是 UNIVERSAL 标签号的保留值，不是所有标签类的禁区。
- `SEQUENCE_OF/SET_OF` 的 `element_type_id` 为 0、越界或引用未注册类型：返回 `ASNBER_E_SCHEMA_TYPE`。
- 其他 `kind` 的 `element_type_id != 0`：非法。
- `ANY` + `IMPLICIT`：非法，返回 `ASNBER_E_SCHEMA_TYPE`。
- `ANY` + `DEFAULT`：必须 `tag_class = UNIVERSAL`、`tag_number = 0`，表示无外层包装；`tag_class` 非 UNIVERSAL 或 `tag_number != 0` 非法。
- `ANY` + `EXPLICIT`：允许非 UNIVERSAL 的 `tag_class/tag_number` 作为外层显式包装；`tag_class = UNIVERSAL` 非法。
- `ANY` 带类型级约束返回 `ASNBER_E_SCHEMA_TYPE`；带字段返回 `ASNBER_E_SCHEMA_FIELD`。`ANY` 可作为 `SEQUENCE_OF`/`SET_OF` 的 `element_type_id` 目标（例如 `SET SIZE (1..MAX) OF ANY`）。

ANY 节点的语义（与运行时注册路径一致）：

- 无包装形态解码时消费**恰好一个完整 TLV**，保留原始 tag/len/content 字节，不建立子节点；`child_count = 0`。
- EXPLICIT 包装形态把节点建模为外层包装节点：完整 TLV 为外层，`content` 返回**内层原始 TLV**（不是内层的 content）；`child_count = 0`；外层必须是构造型且恰好含一个内层 TLV，否则 `ASNBER_E_SCHEMA_TYPE`。
- 无包装形态的原始完整 TLV 可原样回读；原始内容字节（不含 tag/len）可读，构造型 ANY 同样返回该切片。
- 编码：无 schema 的通用编码器直接写回保留的原始 TLV，不再加包装层，允许 BER 源往返；schema 感知 DER 编码对 EXPLICIT ANY 按 schema 重新加外层包装，对无包装 ANY 写回原始 TLV，但要求保留的原始 TLV 是规范 DER（非规范源返回 `ASNBER_E_NON_CANONICAL`，不做隐式重新编码）；节点缺少原始 TLV 或状态不一致时返回 `ASNBER_E_INVALID_STATE`。
- SEQUENCE 内 `tag_mode = DEFAULT` 的 ANY 字段必须是该 SEQUENCE 的最后一个字段，否则 `asnber_schema_seal` 返回 `ASNBER_E_SCHEMA_TYPE`；EXPLICIT ANY 的位置不受限，但外层标签须满足唯一性；SET 中不得出现 DEFAULT 形态的 ANY 字段。
- `format_version` 仍为 1.0：`kind = 6` 与 EXPLICIT ANY 直接纳入当前格式，不升 minor。名称表同样直接纳入 1.0，不升 minor（通过 `header_size` 108 分档识别）。

类型编号规则：

- 头部 `type_count` 记作 `N` 时，类型编号取值为 `1..N`，`0` 表示无效引用；第 `id` 条记录位于 `type_table_offset + (id - 1) * 48`。
- `type_count = 0` 表示没有类型；最大有效编号等于 `type_count`，不存在编号为 `type_count + 1` 的类型。
- `element_type_id` 为 `0` 表示“无元素类型”；`SEQUENCE_OF/SET_OF` 必须使用 `1..N` 的元素类型编号。
- `field_start`、`constraint_start` 是表内数组下标，仍从 0 开始；只有跨引用的 `type_id`、`element_type_id`、`default_index` 使用“0 = 无效、有效从 1 起”的规则。
- 类型编号是描述表**内部引用**，不是公共契约：生成器按“具名类型先按源码顺序、合成类型随后”分配编号，因此模块追加具名类型会整体后移既有合成类型编号。检入表的逐字节不变**不是**回归契约；模块回归依据是测试全绿，加 `ASNBER_CMS_REGENERATE_TABLE=ON` 下生成产物与检入产物的逐字节自校验。

可达裁剪（`asnberc --trim-schema`）不改变描述表格式：裁剪只减少类型、字段、
约束、默认值与名称记录，并让保留类型按原顺序连续重编为 `1..N`；加载器
仍按 `1..type_count` 校验引用。全量与 certificate 变体使用相同的生成符号
`kPKIXFlattened2009Schema`，因此两份表不能链接进同一个二进制。

`[0] EXPLICIT CHOICE` 的建模示例：

```text
ExampleChoice ::= CHOICE { intValue INTEGER, textValue UTF8String }
WrappedChoice ::= [0] EXPLICIT ExampleChoice
```

对应 `WrappedChoice` 的类型记录关键字段：`kind = 3`（CHOICE）、`tag_mode = 1`（EXPLICIT）、`tag_class = 2`（CONTEXT）、`tag_number = 0`、`element_type_id = 0`。解码时先剥离外层 `[0]` 显式包装，再按 `ExampleChoice` 的分支标签选择。

## 5. 字段表

字段表为定长记录数组，每条 **32 字节**：

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | `name_off` | 字段名偏移；不得为 0 |
| 4 | 4 | `type_id` | 类型编号；有效范围 `1..type_count`，`0` 为无效引用；记录下标为 `type_id - 1` |
| 8 | 2 | `flags` | 位 0 = `OPTIONAL`，位 1 = `EXTENSION`；其余位必须为 0 |
| 10 | 2 | `reserved0` | 必须为 0 |
| 12 | 4 | `default_index` | 默认值表索引；有效范围 `1..default_count`，`0` 表示无 DEFAULT；记录下标为 `default_index - 1` |
| 16 | 4 | `constraint_start` | 字段级约束在约束表中的起始下标 |
| 20 | 4 | `constraint_count` | 字段级约束数量 |
| 24 | 4 | `reserved1` | 必须为 0 |
| 28 | 4 | `reserved2` | 必须为 0 |

规则：

- `DEFAULT` 只由 `default_index != 0` 派生，不设独立标志位；`default_count = N` 时有效索引为 `1..N`，最大索引等于 `default_count`。
- 字段级约束与类型级约束**同时生效**，按“类型约束先、字段约束后”的顺序校验。
- `OPTIONAL` 与 `DEFAULT` 可以并存；`DEFAULT` 字段在编码时按规范省略。
- `EXTENSION` 表示该字段位于扩展标记之后；扩展字段本身仍可带 `OPTIONAL`。
- `field_start/field_count` 只能由所属类型记录引用；字段记录不允许跨类型共享区间。

## 6. 约束表

约束表为定长记录数组，每条 **48 字节**：

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 2 | `kind` | 0 = RANGE，1 = SIZE，2 = ENUM，3 = MAX，4 = BIGINT_RANGE |
| 2 | 2 | `flags` | 位 0 = 下界无界，位 1 = 上界无界；其余位必须为 0 |
| 4 | 4 | `enum_off` | ENUM 取值数组在文件中的偏移；其他 kind 为 0 |
| 8 | 4 | `enum_count` | ENUM 取值个数；其他 kind 为 0 |
| 12 | 4 | `lower_decimal_off` | 下界十进制文本偏移；0 表示使用 `lower_value` |
| 16 | 4 | `lower_decimal_size` | 下界十进制文本字节数；0 表示使用 `lower_value` |
| 20 | 4 | `upper_decimal_off` | 上界十进制文本偏移 |
| 24 | 4 | `upper_decimal_size` | 上界十进制文本字节数 |
| 28 | 8 | `lower_value` | 下界小整数（有符号 64 位） |
| 36 | 8 | `upper_value` | 上界小整数（有符号 64 位） |
| 44 | 4 | `reserved` | 必须为 0 |

语义：

| `kind` | 语义 | 边界来源 | 适用 |
| --- | --- | --- | --- |
| `RANGE` | 闭区间值域 `lower..upper` | 小整数；超出时用十进制 | INTEGER、ENUMERATED |
| `SIZE` | 闭区间长度/元素数 | 小整数 | 字符串、OCTET STRING、BIT STRING、SEQUENCE OF、SET OF |
| `ENUM` | 枚举取值集合 | `enum_off` 指向 `int64` 数组，小端 8 字节 | ENUMERATED、带命名的 INTEGER |
| `MAX` | `(0..MAX)` 的简写 | 下界 0，上界无界 | 非负 INTEGER |
| `BIGINT_RANGE` | 任意精度闭区间 | 必须使用十进制文本 | INTEGER |

规则：

- `RANGE`/`SIZE` 的 `lower > upper` 非法；`SIZE` 的下界不得为负。
- `MAX` 表示上界无界：`upper` 的 `is_unbounded` 必须为 1；下界固定为 0，不得另行给出 lower 十进制文本或非零 `lower_value`。
- `kind = BIGINT_RANGE` 时，`lower_decimal`/`upper_decimal` 至少一侧必须存在；缺失一侧按无界处理；两侧都存在时按数值比较且 `lower <= upper`。
- `enum_count = 0` 的 `ENUM` 非法；枚举取值不得重复；`enum_off` 必须 8 字节对齐且区间完整。
- 同一类型/字段的多条约束按表顺序**全部**校验（逻辑与，即交集语义），不提供析取。
- 十进制文本必须符合 `^-?(0|[1-9][0-9]*)$`：可选负号、至少一位数字、除 `"0"` 外无前导零、无正号、无空白、无科学计数法；`"-0"` 非法。
- `SIZE` 的上下界单位由被约束类型决定：OCTET STRING 与各字符串类型按**字节数**（字符串按其 DER 编码内容字节数）；`SEQUENCE OF`/`SET OF` 按**元素数**。
- 上述约束规则违反时：描述表路径返回 `ASNBER_E_SCHEMA_FORMAT`；运行时注册路径返回 `ASNBER_E_SCHEMA_CONSTRAINT`。

## 7. 默认值表

默认值表为定长记录数组，每条 **8 字节**：

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | `data_offset` | 规范 DER TLV 在文件中的绝对偏移 |
| 4 | 4 | `data_size` | TLV 字节数；不得为 0 |

规则：

- 默认值必须是**可规范化的完整 DER TLV**（含标签与长度），不能是裸内容。
- 核心在 `asnber_schema_add_field` / `asnber_schema_load` 时解析并校验该 TLV；解析失败返回 `ASNBER_E_SCHEMA_DEFAULT`。
- 阶段边界：当前只做**结构级规范校验**（最短长度、禁止不定长、递归构造自洽、无尾随字节，以及 BOOLEAN/INTEGER/ENUMERATED/BIT STRING/NULL 的规范值形式）；“重新编码后与原始字节逐字节一致”依赖 DER 编码器，列入编码阶段里程碑（见[里程碑与分期](09-里程碑与分期.md)），本阶段不实现。
- 默认值区不得与头部或各表重叠；允许位于字符串池之后。
- 同一个默认值可被多个字段通过不同 `default_index` 引用，但生成器应复用相同记录以保证可复现。

## 8. 版本兼容策略

- `format_version = major << 16 | minor`。
- 核心只接受**主版本相同且次版本不大于库支持次版本**的描述表；主版本不同或次版本过新返回 `ASNBER_E_SCHEMA_FORMAT`。
- 当前版本矩阵（`asnber_schema_table_t.format_version` 必须与头部值完全相等，否则同样返回 `ASNBER_E_SCHEMA_FORMAT`）：

  | 头部 `format_version` | 结果 |
  | --- | --- |
  | `0.0`（`0x00000000`） | 拒绝（主版本不同） |
  | `1.0`（`0x00010000`） | 接受（当前基线） |
  | `1.1`（`0x00010001`） | 拒绝（次版本高于库支持的 0） |
  | `2.0`（`0x00020000`） | 拒绝（主版本不同） |

- `header_size` 分档：96–99 不读取 `root_type_id` 与名称表；100–107 读取 `root_type_id`、无名称表；108 读取名称表；大于 108 的尾部忽略。96、100、108 是测试锁定的三个有效档位，104 只作为“任意合法中间值”验证。
- 次版本升级只允许“纯追加”：新增表或新增字段必须通过头部尾部追加字段表达，不得改变既有记录宽度与偏移语义；旧加载器把 `header_size` 超出基线的尾部字段视为未知并忽略。当前基线为 108，`header_size` 为 100–107 的描述表按旧基线读取（无名称表）。
- 头部 `header_size` 必须 `>= 96`；新增头部字段时提升次版本并把 `header_size` 增大到覆盖新字段，表区间仍必须位于 `[header_size, total_size)`。
- 不提供“旧格式自动迁移”；`asnberc` 与核心必须使用同一 `format_version`。
- 核心拒绝加载时不得部分构建类型树；输出 schema 置 `NULL`。

## 9. 越界与恶意输入校验

加载前按以下顺序校验，任一失败返回对应错误码，不进行任何分配以外的副作用：

| 检查项 | 失败错误码 |
| --- | --- |
| `table->struct_size` 错误 | `ASNBER_E_INVALID_CONFIG` |
| `data == NULL` 或 `size == 0` | `ASNBER_E_INVALID_ARG` |
| `magic` 不匹配 | `ASNBER_E_SCHEMA_FORMAT` |
| `format_version` 不支持 | `ASNBER_E_SCHEMA_FORMAT` |
| `header_size < 96` 或 `header_size > total_size` | `ASNBER_E_SCHEMA_FORMAT` |
| `endianness` 标记不匹配 | `ASNBER_E_SCHEMA_FORMAT` |
| `total_size != size` | `ASNBER_E_SCHEMA_FORMAT` |
| `table->format_version != 头部 format_version` | `ASNBER_E_SCHEMA_FORMAT` |
| `root_type_id` 非 0 且大于 `type_count` | `ASNBER_E_SCHEMA_FORMAT` |
| 预留字段非 0 | `ASNBER_E_SCHEMA_FORMAT` |
| 表偏移/计数溢出、越界、区间重叠 | `ASNBER_E_SCHEMA_FORMAT` |
| 字符串越界、未终止 | `ASNBER_E_SCHEMA_FORMAT` |
| `kind`/`tag_mode`/`tag_class` 越界 | `ASNBER_E_SCHEMA_TYPE` |
| `type_id` 越界 | `ASNBER_E_SCHEMA_TYPE` |
| 字段区间越界 | `ASNBER_E_SCHEMA_FIELD` |
| 约束区间/枚举数组越界 | `ASNBER_E_SCHEMA_CONSTRAINT` |
| 约束语义规则违反（RANGE/BIGINT/MAX/ENUM/SIZE，见第 6 节） | `ASNBER_E_SCHEMA_FORMAT` |
| 默认值下标越界或 DER 非法 | `ASNBER_E_SCHEMA_DEFAULT` |
| 名称表区间/记录字段非法（见第 17 节） | `ASNBER_E_SCHEMA_FORMAT` |
| 重复标签/`CHOICE` 分支冲突 | `ASNBER_E_SCHEMA_TYPE` |
| `flags` 位 0 为 0 或 `checksum_alg != 1` | `ASNBER_E_SCHEMA_FORMAT` |
| `table->size > max_input_bytes` | `ASNBER_E_INPUT_LIMIT` |
| 校验和不匹配 | `ASNBER_E_SCHEMA_FORMAT` |

强制规则：

- 所有偏移与计数在相加/相乘前做溢出检查；禁止截断到 `uint32_t`。
- 任何表记录不得跨出 `total_size`；任何字符串不得跨出字符串池。
- 加载只受 `max_input_bytes` 约束；`max_nodes` 是 DOM 节点预算，不适用于 schema 描述表加载，也不存在“记录→节点”换算。
- 非法文件不得留下部分 schema；失败时销毁上下文内已分配的中间对象。

## 10. 结构检查

### 10.1 重复标签检查

| 容器 | 规则 |
| --- | --- |
| `SET` | 所有字段的有效外层标签必须两两不同；冲突返回 `ASNBER_E_SCHEMA_TYPE` |
| `CHOICE` | 所有分支的有效外层标签**集合**必须两两不相交；无法在有限展开内确定标签集合时同样失败 |
| `SEQUENCE` | 允许字段重复标签；但 `OPTIONAL`/`DEFAULT` 字段的标签不得与任何后继字段标签相同，否则视为歧义并失败 |
| `SEQUENCE_OF`/`SET_OF` | 只有一个元素类型，不参与重复标签检查 |

有效外层标签的计算：

- `SIMPLE`：`tag_class + tag_number`。
- `SEQUENCE`/`SET`/`SEQUENCE_OF`/`SET_OF`：自身有效标签；默认标签按 UNIVERSAL 16/17 计算。
- `EXPLICIT`：外层显式标签。
- `IMPLICIT`：替换后的标签。
- `CHOICE`：所有分支有效标签的并集；分支为 `CHOICE` 时递归展开，展开深度上限 32。

### 10.2 引用检查

- 字段 `type_id`、`element_type_id` 必须指向已存在的类型；有效类型编号从 1 连续分配到 `type_count`，`0` 仅表示无效/无引用。
- `root_type_id` 为 0 表示无单一根（允许多个顶层类型并列）；非 0 必须指向 `1..type_count` 内的类型记录。
- 允许递归类型（`SEQUENCE` 字段引用祖先类型、`CHOICE` 分支递归）；递归不视为错误，运行期由 `max_depth` 限制。
- 不允许“无标签可推进”的递归：若 `CHOICE` 的标签集合展开在 32 层内仍无法确定，返回 `ASNBER_E_SCHEMA_TYPE`。
- 所有名称必须非空且唯一：类型名在**合并后的单一名称空间**内唯一，字段名在所属类型内唯一；重复返回 `ASNBER_E_SCHEMA_TYPE` / `ASNBER_E_SCHEMA_FIELD`。多模块输入时，`asnberc` 在生成期对跨模块同名类型改名来保证该唯一性（见 §13.1）。

### 10.3 字段标志与容器约束

| 检查项 | 规则 | 失败错误码 |
| --- | --- | --- |
| `CHOICE` 分支字段 | 分支字段不得设置 `OPTIONAL`、`DEFAULT`（`default_index != 0`）或 `EXTENSION`；任一出现即失败 | `ASNBER_E_SCHEMA_FIELD` |
| `SEQUENCE_OF`/`SET_OF` | 不得添加任何字段（`field_count` 必须为 0） | `ASNBER_E_SCHEMA_FIELD` |

这两项在 `asnber_schema_seal` 与 `asnber_schema_load` 两条路径都必须执行；`add_field` 阶段可以提前拒绝，但不能替代封存期检查。

## 11. C 数组输出规则

`asnberc` 生成 C 源文件时，必须输出**与二进制描述表逐字节相同**的 `uint8_t[]`：

```c
/* 由 asnberc 生成，请勿手工修改。 */
#include <stddef.h>
#include <stdint.h>

const uint8_t kExampleSchema[] = {
    0x41, 0x53, 0x4E, 0x31, 0x53, 0x43, 0x48, 0x1A,
    /* ... 其余字节 ... */
};

const size_t kExampleSchema_size = sizeof(kExampleSchema);
```

规则：

- 类型必须是 `const uint8_t[]`，不得生成结构体数组、位域、联合或依赖编译器布局的类型。
- 核心读取 C 数组时使用显式小端读取函数，逐字段组合；**不把 `data` 强转为结构体指针**。
- 8 字节对齐只作为性能优化：生成器应让各表偏移按 8 字节对齐；核心不得要求 `data` 地址对齐，也不得因未对齐而失败。
- 数组长度必须等于头部 `total_size`；生成器同时输出 `_size` 常量，核心仍以 `asnber_schema_table_t.size` 为准。
- 生成顺序固定：头部、字符串池、类型表、字段表、约束表、默认值表、默认值数据；填充字节显式写 0。
- 输出不得包含时间戳、绝对路径、随机数或主机相关信息；相同输入必须得到相同字节。
- 二进制输出与 C 数组共用同一内存模型，区别仅在承载形式。

## 12. 命令行（冻结）与尚未冻结的实现细节

### 12.1 命令行（冻结）

命令行参数已冻结，不得更改：

```text
asnberc [OPTIONS] <input.asn1>...
  -o, --output-bin <PATH>    写二进制描述表
  -c, --output-c <PATH>      写 C 数组源文件
  -I, --include <DIR>        追加模块搜索目录（可重复，顺序敏感）
      --root <TYPE|MODULE.TYPE>
                             设置根类型（默认不设，header root_type_id = 0）
      --diagnostics <LEVEL>  minimal|normal|verbose（默认 normal）
      --version              打印 `asnberc <版本>`
  -h, --help
```

规则：

- 位置参数为 `1..N` 个 `.asn1` 文件，按给出顺序构成显式输入模块；单文件调用行为与字节输出不变。
- `-I`/`--include` 可重复；模块 `M` 在搜索路径中对应文件 `M.asn1`（大小写敏感、完全同名）。搜索顺序为各显式输入文件所在目录（命令行顺序）→ 各 `-I` 目录（给出顺序），首个命中生效。
- 至少给出 `-o`/`-c` 之一；两者都缺省时按命令行用法错误处理（退出码 2）。
- `--root` 未给出时头部 `root_type_id = 0`；给出时必须指向已定义类型，否则报 `ASNBERC_E_UNDEFINED_TYPE`(9002)。多模块输入支持 `--root Module.Type` 精确定位；未限定形式在多个模块定义同名类型时报 `ASNBERC_E_DUPLICATE_TYPE`(9003)。
- 多文件输入的合并顺序：显式输入按命令行顺序在前，按需发现的模块随后按模块名字典序；输出仍是一张描述表，格式与版本不变。
- 诊断级别：`minimal` 只输出 error；`normal` 输出 error 与 warning；`verbose` 额外在 stderr 输出一行生成摘要（类型数、具名类型数、合成类型数、字节数）。
- 每次生成必须全部成功后才写文件，不得留下半成品；单个文件写入失败时删除该文件。
- 同一输入两次运行必须逐字节一致。

## 13. `asnberc` 一期语法范围（MVP）

### 13.1 必须支持

| 类别 | 范围 |
| --- | --- |
| 基本类型 | BOOLEAN、INTEGER、ENUMERATED、BIT STRING、OCTET STRING、NULL、OBJECT IDENTIFIER、RELATIVE-OID、UTF8String、PrintableString、IA5String、VisibleString、NumericString、BMPString、UniversalString、TeletexString（T61String）、UTCTime、GeneralizedTime |
| 构造类型 | SEQUENCE、SET、CHOICE、SEQUENCE OF、SET OF |
| 标签 | 模块级 `DEFINITIONS EXPLICIT/IMPLICIT/AUTOMATIC TAGS`；类型级 `[n]`、`[n] IMPLICIT`、`[n] EXPLICIT` |
| 约束 | 单值、值域 `(a..b)`、`SIZE (...)`、`MAX`、`MIN`、扩展标记 `...` |
| 引用 | 同模块类型引用与多模块 `IMPORTS ... FROM Module`；`EXPORTS` 控制跨模块可见性（缺省全导出），导入失败按 9002/9003 诊断；多模块合并为一张描述表 |
| 参数化 | 支持单类型参数化定义（`Foo { Type }`）与实例化（`Foo { INTEGER }`），语义阶段把形参替换为实参、生成与人工展平逐字节一致的描述表；值参数与多参数仍报 `ASNBERC_E_UNSUPPORTED_CONSTRUCT`(9006) |
| 值 | 仅解析生成描述表所需的 OID/整数/布尔等常量；不做通用值求值 |

一期输入既可以是自包含的展平模块（见第 14 节），也可以是多模块输入：`asnberc` 按 `IMPORTS ... FROM Module` 绑定跨模块引用，按合并顺序展平为**一张**描述表，格式与版本不变。模块按 `M.asn1` 命名约定在输入目录与 `-I` 目录中发现；被导入模块缺失、符号未定义/未导出报 9002，本地同名冲突、重复模块名与根类型歧义报 9003，循环导入报 9002 并停止。跨模块同名类型由生成器改名为 `Foo-<Module>`，并让 `--root Foo` 报歧义、`--root Module.Foo` 精确定位。直接消费原始 RFC 模块（`CLASS`/信息对象集）仍不在本期范围，见 `docs/09`。

### 13.2 一期不支持

| 构造 | 处理方式 |
| --- | --- |
| `CLASS`、`WITH SYNTAX`、信息对象、信息对象集 | 采用预展开模块方案，见第 14 节；原版模块保留作参考 |
| 值参数化、多参数参数化类型 | 报 `ASNBERC_E_UNSUPPORTED_CONSTRUCT` |
| `COMPONENTS OF` | 一期不支持，报 `ASNBERC_E_UNSUPPORTED_CONSTRUCT` |
| 通用值集合运算、`WITH COMPONENTS`、`PATTERN` | 一期不支持 |
| 宏定义、用户自定义编码规则 | 不支持 |

**当前实现状态（本轮 MVP）：**

- 已实现：§13.1 表中**全部条目**（含多模块 `IMPORTS`/`EXPORTS` 与单表合并、单类型参数化定义与实例化）；`ANY`（含 `[n] EXPLICIT ANY`）已可用并映射为 `kind = 6`。
- 合成类型：匿名内联结构、标签克隆、共享裸 ANY 会生成以 `$` 开头的合成类型记录；具名类型始终占用 id `1..N` 且名字不以 `$` 开头，合成类型追加在具名类型之后。参数化实例化生成的合成类型名形如 `模板名-实参`（如 `AlgorithmIdentifier-INTEGER`），按名称排序后分配 id，与人工展平的具名类型等价。
- 明确诊断、后续再做：值参数化、多参数参数化 → `ASNBERC_E_UNSUPPORTED_CONSTRUCT`(9006)；参数化实例化错误（参数数不匹配、对非模板实例化、模板未实例化直接引用）→ `ASNBERC_E_PARAM_INSTANTIATION`(9008)；`CLASS`/`WITH SYNTAX`/信息对象集仍通过预展开模块输入。
- 多模块约束：循环导入按 9002 拒绝；`EXPORTS` 只影响跨模块可见性；跨模块同名类型按 `Foo-<Module>` 改名写入描述表。
- 已定义：`BIT STRING` 命名位与 `ENUMERATED`/`INTEGER` 数值名进入名称表（见第 17 节），不再存在“仅解析、不进入描述表”的缺口。

### 13.3 参数化实例化

- 每个不同的实参组合生成**独立的类型条目**，不复用基类型的编号。
- 实例化名称使用 `模板名-实参` 的可打印 ASCII 形式（非字母数字字符转 `-`），如 `AlgorithmIdentifier-INTEGER`；与人工展平的命名一致，保证描述表逐字节等价。
- 实例化后的类型必须再次参与重复标签与引用检查；实参替换后若产生非法标签组合，报 `ASNBERC_E_PARAM_INSTANTIATION`(9008)。
- 参数数不匹配、对非模板类型实例化、模板未实例化直接引用，均报 `ASNBERC_E_PARAM_INSTANTIATION`(9008)。
- 模板类型本身（`params` 非空）不进入描述表；只有实例化后的合成类型写入。

当前实现支持**单类型参数**的参数化定义与实例化；值参数与多参数仍报 `ASNBERC_E_UNSUPPORTED_CONSTRUCT`(9006)，留后续。

## 14. `CLASS` / `WITH SYNTAX` / 信息对象集：预展开模块方案

一期**不直接解析** CLASS、WITH SYNTAX 与信息对象集；仓库提供由 RFC 5912 派生、已展平的模块作为 `asnberc` 输入，原版模块保留作参考与比对。

### 14.1 目录与来源约定

| 内容 | 约定位置 | 用途 |
| --- | --- | --- |
| 展平模块 | `modules/pkix/asn1/`（按模块名分文件） | `asnberc` 的一期输入 |
| 原版模块 | `modules/pkix/asn1/reference/rfc5912/` | 只作参考，不参与生成 |
| 生成产物 | `modules/pkix/src/` 下的描述表 C 数组 | 随模块发布 |

规则：

- 展平模块必须是合法 ASN.1 模块，可直接被 `asnberc` 解析；不得包含 CLASS、WITH SYNTAX 或信息对象。
- 展平只允许做“信息对象展开为具体类型/常量”的机械替换，不得改变任何类型的标签、约束或字段顺序。
- 原版模块不参与构建，也不得被核心或模块公共头引用。
- 当前仓库已产出展平模块 `modules/pkix/asn1/PKIX-Flattened-2009.asn1`，原版模块与展平结果的对账表见 `modules/pkix/asn1/reconciliation.md`；`asnberc` 一期启动与 PKIX 描述表生成以该文件为输入。

### 14.2 展平等价性校验

CI 必须执行以下检查，任一失败即阻断：

1. **类型集合逐一对应**：原版模块（按第 15 节勘误修正后）声明的每个类型，在展平模块中恰好存在一个同名类型；不得新增、删除或改名。
2. **字段与顺序一致**：每个类型的字段名、顺序、`OPTIONAL`、`DEFAULT`、扩展标记位置与展平前一致。
3. **标签一致**：每个类型的有效标签与标注方式在展平前后一致。
4. **约束一致**：SIZE、值域、枚举与 MAX 约束在展平前后一致。
5. **编码等价**：抽样类型在展平前后生成相同 DER 编码；差异视为失败。
6. **可复现**：同一原版模块与同一展平规则必须生成相同展平结果。

补充说明：第 15.2 节列出的 **8 条 Verified 勘误不改变任何保留类型的标签、字段或约束**；勘误修正只影响模块归属、导入引用与信息对象 `TYPE` 关键字等生成期细节，因此第 1–5 项对账结论不受影响。

## 16. 输出形态与诊断格式（冻结）

### 16.1 输出形态

- `asnberc` 支持两种输出：C 数组源文件与二进制描述表；二者必须逐字节同布局。
- C 数组输出文件路径由 `-c` 指定；数组符号名由模块名派生，生成器输出稳定符号：`k<Module>Schema`、`k<Module>Schema_size`。
- 符号名派生规则：取模块名，去掉**所有非 ASCII 字母数字字符**（如 `-`、`_`、`.`），保留大小写，前缀 `k`、后缀 `Schema`；长度常量在同名前缀下追加 `_size`。例：模块 `PKIX-Flattened-2009` → `kPKIXFlattened2009Schema` / `kPKIXFlattened2009Schema_size`。
- 生成文件头固定包含“由 asnberc 生成，请勿手工修改”的注释（C 源文件首行为 `/* 由 asnberc 生成，请勿手工修改。 */`）；不写时间戳。
- C 数组按每行 **12 个字节字面量** 换行输出，字节字面量固定为两位大写十六进制（如 `0x41`）。
- 生成失败时不产生半成品文件；已存在的旧产物不得被部分覆盖。

### 16.2 诊断输出

每条诊断固定为单行：

```text
<file>:<line>:<column>: <severity>: <code>: <message>
```

- `severity`：`error` 或 `warning`。
- `line`/`column` 从 1 开始；未知时写 `0`。
- `file` 为输入文件路径，按命令行原样输出。
- 诊断按 `file`、`line`、`column`、`code` 升序稳定输出。
- 退出码：`0` 成功；`1` 存在 error；`2` 命令行用法错误；`3` 输入/输出 IO 失败。

错误码：

| 错误码 | 值 | 含义 |
| --- | --- | --- |
| `ASNBERC_E_SYNTAX` | 9001 | 词法/语法错误 |
| `ASNBERC_E_UNDEFINED_TYPE` | 9002 | 引用了未定义类型 |
| `ASNBERC_E_DUPLICATE_TYPE` | 9003 | 类型重名 |
| `ASNBERC_E_DUPLICATE_FIELD` | 9004 | 字段重名 |
| `ASNBERC_E_TAG_CONFLICT` | 9005 | 重复标签或 `CHOICE` 分支冲突 |
| `ASNBERC_E_UNSUPPORTED_CONSTRUCT` | 9006 | 一期不支持的语法构造 |
| `ASNBERC_E_PARAM_INSTANTIATION` | 9008 | 参数化实例化失败 |
| `ASNBERC_E_CONSTRAINT_INVALID` | 9009 | 约束非法或不可满足 |
| `ASNBERC_E_OUTPUT_IO` | 9010 | 输出写入失败 |
| `ASNBERC_E_INTERNAL` | 9099 | 工具内部不变量破坏 |

警告码：

| 警告码 | 值 | 含义 |
| --- | --- | --- |
| `ASNBERC_W_UNUSED_IMPORT` | 9101 | 导入未使用 |
| `ASNBERC_W_DEPRECATED_SYNTAX` | 9102 | 使用了已弃用但可接受的语法 |

诊断消息固定为英文 ASCII；本地化不在基线内。

## 17. 名称表

名称表表达 `BIT STRING` 的命名位与 `ENUMERATED`/`INTEGER` 的数值名。它随 1.0 格式直接引入，不升 `minor`；`header_size < 108` 的描述表没有名称表。

名称表为定长记录数组，每条 **24 字节**，小端：

| 偏移 | 宽度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | `type_id` | 所属类型编号，1-based；必须在 `1..type_count` |
| 4 | 4 | `name_off` | 名称在字符串池中的偏移；不得为 0，必须解析到有效 NUL 结尾 ASCII 名称 |
| 8 | 2 | `kind` | 0 = `BIT_NAME`（BIT STRING 命名位），1 = `NUMBER_NAME`（数值名） |
| 10 | 2 | `flags` | 位 0 = `EXTENSION`（扩展值）；其余位必须为 0 |
| 12 | 4 | `reserved0` | 必须为 0 |
| 16 | 8 | `value` | `BIT_NAME` 为位号（无符号，`0..65535`）；`NUMBER_NAME` 为有符号 64 位整数值 |

记录顺序不强制；同一类型内不得混用 `BIT_NAME` 与 `NUMBER_NAME`。

语义与校验（违反一律返回 `ASNBER_E_SCHEMA_FORMAT`，错误详情 `offset` 指向具体字段）：

| 检查项 | 规则 |
| --- | --- |
| 区间 | 名称表必须位于 `[header_size, total_size)` 内、记录数组完整，且不与字符串池、类型表、字段表、约束表、默认值表或默认值数据重叠 |
| `type_id` | 不得为 0，不得大于 `type_count` |
| `kind` | 不得大于 1 |
| `flags` | 除位 0 外必须为 0 |
| `reserved0` | 必须为 0 |
| `name_off` | 沿用字符串池规则：非 0、在池内、NUL 结尾 |
| 重复 | 同一类型内名称不得重复；同 `kind` 的 `value` 不得重复 |
| `BIT_NAME` 类型 | 所属类型必须 `kind = SIMPLE`、`tag_class = UNIVERSAL`、`tag_number = 3`（BIT STRING） |
| `BIT_NAME` 标志 | `flags` 位 0 必须为 0（位名不得标记为扩展值） |
| `BIT_NAME` 位号 | 若该类型或其字段上存在有限上界的 `SIZE` 约束，位号必须 `< 该上界`（多条取最小上界）；否则必须 `<= 65535` |
| `NUMBER_NAME` 类型 | 所属类型必须 `kind = SIMPLE`、`tag_class = UNIVERSAL`、`tag_number` 为 10（ENUMERATED）或 2（INTEGER） |
| `NUMBER_NAME` 扩展标志 | `flags` 位 0 只允许在所属类型 `flags` 含 `ASNBER_TYPE_EXTENSIBLE` 时出现 |

说明：

- 位号上界只使用**有限上界**的 `SIZE` 约束；`SIZE (0..MAX)` 等无界上界不构成上限。
- 同一类型内的重复记录、额外顺序限制均不引入；只拒绝“重复名称/同 kind 重复数值”。
- 运行时注册路径不产生名称表：`asnber_schema_create` 得到的 schema 名称为空，查询 API 返回“无名称”。描述表加载路径在构建类型树时复制名称，失败时整体销毁，不返回部分树。
- 名称查询 API 见 `docs/02-C-API规范.md` 6.2（`asnber_schema_name_count`、`asnber_schema_name_at`、`asnber_schema_name_for_bit`、`asnber_schema_name_for_value`、`asnber_schema_value_for_name`）。
