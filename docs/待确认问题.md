### 3.2 分层、版本、依赖与描述表决策 D11–D20

| 编号 | 决策 |
| --- | --- |
| D11 | 通用 ASN.1 库 + 独立标准模块：核心零领域知识，X.509/PKIX、CMS、PKCS 以独立包提供，复用公开 RFC 模块 |
| D12 | 模板机制在核心：已编译描述表加载与运行时注册 API 指向同一类型树；核心不解析 `.asn1` 文本，不内置标准表 |
| D13 | `asnberc` 负责 `.asn1` 解析、语义校验与描述表生成；一期 MVP，二期完善；模块表由工具生成 |
| D14 | CER 需求触发，不列入二期固定范围 |
| D15 | PER/UPER 暂不规划，写明重启条件 |
| D16 | 大整数只读视图 + 十进制导出，不做运算；核心一期 |
| D17 | 时间结构化只读解析，不做时区归一；核心一期 |
| D18 | 版本一致性：`project(... VERSION ...)` 为唯一真源，CMake 生成版本头；SONAME、包版本文件与 CI 断言均由其派生；运行时提供 `asnber_version` 与 `asnber_version_check` |
| D19 | 第三方依赖与许可证：运行库零第三方；测试/工具仅宽松许可；清单登记 + 脚本/CI 检查；MIT + `THIRD_PARTY_NOTICES.md` 分发 |
| D20 | 类型种类 `kind` 派生构造性，`tag_mode` 只表显式覆盖，模块默认标注记录在描述表头部；约束结构化、挂类型、可多条；DEFAULT 存规范 DER TLV；描述表为 `uint8_t[]` 显式小端布局；一期输入支持自包含展平模块与多模块 `IMPORTS`（A 阶段落地，单表合并），参数化支持单类型展开（值参数与多参数报 9006），`CLASS`/信息对象集以预展开模块输入（由 [ADR-0012](adr/0012-标准模块路线与只读边界.md) 修订） |

> 标准结构表只存在于 `asnber-pkix` 等模块；核心不感知领域概念，也不携带任何预生成表。

## 4. 处理规则

1. 任何后续阶段问题在启动前必须转为“已确认”并写入 ADR；未确认前不得实现。
2. 若发现新的阻塞一期问题，立即更新本文与[覆盖度清单](基线覆盖度清单.md)，并暂停相关实现。
3. 本清单不记录纯技术细节（如具体函数命名），后者由编码规范与评审处理。
