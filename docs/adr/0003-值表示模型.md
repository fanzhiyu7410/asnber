# ADR-0003：通用 DOM 与输入所有权

- 状态：已确认（用户批准，2026-11-03）
- 日期：2026-11-03
- 关联：[ASN.1 能力范围](../03-ASN1能力范围.md)、[数据表示与内存模型](../04-数据与内存模型.md)

## 背景

需要在不解析 `.asn1` 模式的前提下解析任意 BER/DER 数据；同时要兼顾大输入的内存占用与嵌入式场景。值表示方式与输入是否复制，直接决定性能、所有权规则和错误清理复杂度。

## 决策

1. **通用 DOM 为主线**：解码输出带标签的节点树，完整保留原始 TLV 偏移与内容切片；未知/扩展字段天然保留。
2. **模板机制是核心一期能力**：在 DOM 之上增加字段命名与结构/约束校验层；不启用时行为与通用 DOM 完全一致。类型描述来自已编译描述表或运行时注册，不来自 `.asn1` 文本解析；标准结构表由独立模块提供，核心不内置。
3. **默认零拷贝借用输入**：
   - `asnber_decode_buffer` 默认引用调用方缓冲，文档存续期间调用方必须保证输入有效。
   - 提供 `ASNBER_DECODE_COPY_INPUT` 选项复制到 arena。
   - reader 路径必然复制/累积到 arena，因为输入块可能被复用。
4. **值惰性解析**：节点只保存原始切片；整数、OID 文本、字符串视图在调用读取函数时生成，OID 结果缓存在 arena。
5. **节点只读**：解码产出的节点不可变；runtime 构树的文档在 `asnber_doc_seal` 前可变，封存后只读。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 全部复制输入 | 大证书/大 CMS 内存翻倍；嵌入式不可接受 |
| 全部零拷贝 | reader 输入块生命周期不可控，易产生悬垂指针 |
| 每节点独立堆分配 | 分配次数多、失败清理复杂、碎片严重 |
| 解析时直接反序列化为业务对象 | 无模式无法做到；且破坏“保留未知字段”能力 |

## 后果

- 文档必须显著标注“借用输入”的生命周期规则，C API 示例与注释都要提示。
- 需要测试覆盖借用/复制两条路径，以及 reader 分块边界。
- 模板校验不得改变节点树布局，否则违反“通用 DOM 主线”。
- 零拷贝意味着输入缓冲区在文档存续期间必须只读；若调用方修改输入，行为未定义（文档明示禁止）。
