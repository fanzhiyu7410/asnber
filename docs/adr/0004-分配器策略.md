# ADR-0004：arena、分配器钩子与静态池

- 状态：已确认（用户批准，2026-11-03）
- 日期：2026-11-03
- 关联：[数据表示与内存模型](../04-数据与内存模型.md)、[C API](../02-C-API规范.md)

## 背景

解码会创建大量生命周期相同的节点、内容副本和惰性视图。逐对象分配与逐对象释放会带来碎片、失败路径复杂和嵌入式不可控。另一方面，宿主可能需要接管分配（调试器、内存池、RTOS），部分嵌入式场景完全不允许堆。

## 决策

1. **文档级 arena 为默认**：文档创建时建立 arena，节点/副本/视图从 arena 分配；文档销毁时整体释放，不提供单节点释放。schema 与输出缓冲属于上下文级分配，不进入文档 arena。
2. **分配器钩子**：`asnber_allocator_t` 提供 `alloc/realloc/free` 与 `user`，由上下文在创建时绑定；所有底层块申请经由钩子。回调不得抛出异常，失败返回 `NULL`。
3. **可选静态池**：上下文可绑定调用方提供的连续内存；启用后上下文级分配与文档 arena 都只从池内分配，耗尽返回 `ASNBER_E_STATIC_POOL_EXHAUSTED`，严禁回退堆。
4. **默认堆**：未提供钩子且未启用静态池时，使用库内封装的 `malloc/realloc/free`。
5. **错误状态不分配内存**：错误码/偏移/深度使用上下文的固定字段，确保 OOM 时仍可读取错误。
6. **预算记账**：分配前检查节点数、输入/输出字节和溢出；所有乘法/加法先检查。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 每节点 `new/delete` | 分配次数多、碎片大、失败清理需逐节点回滚 |
| 全局分配器单例 | 违反“无全局可变状态”与多对象并行 |
| 强制调用方提供分配器 | 增加简单集成方的心智负担；默认堆更易用 |
| 静态池自动扩容/回退堆 | 破坏“无堆”承诺；耗尽应显式失败 |

## 后果

- 节点指针稳定性依赖 arena 不搬迁；arena 块一经分配不移动。
- `realloc` 若由钩子实现，必须保证失败时原块有效；库内部不依赖 `realloc` 原地扩展。
- 静态池尺寸需集成方压测；库不提供自动估算（文档给出估算公式）。
- allocator 钩子和静态池的线程安全由调用方负责；库不额外加锁。
- 测试必须包含失败注入分配器与静态池耗尽路径。
