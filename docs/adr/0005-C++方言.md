# ADR-0005：C++17 且禁用异常/RTTI

- 状态：已确认（用户批准，2026-11-03）
- 日期：2026-11-03
- 关联：[编码规范](../08-编码规范.md)、[构建与移植](../06-构建与移植.md)、[错误模型](../05-错误模型.md)

## 背景

库需要覆盖桌面与嵌入式工具链。异常与 RTTI 会增加二进制体积、运行时依赖与跨 ABI 风险；异常还会让错误路径难以在 C ABI 边界统一。C++17 在主流嵌入式 GCC/Clang 与 MSVC 上均已可用，且提供足够的语言能力。

## 决策

1. **基线标准 C++17**；公共头文件为 C99。允许实验性使用 C++20，但不作为验收条件。
2. **全面禁用异常**：`-fno-exceptions`；MSVC `/EHs-c-` + `_HAS_EXCEPTIONS=0`。不提供“打开异常”的构建选项。
3. **全面禁用 RTTI**：`-fno-rtti`；MSVC `/GR-`。不使用 `dynamic_cast`、`typeid`。
4. **错误码传播**：内部统一返回 `Status`/错误码，输出经参数返回；不使用异常做控制流。
5. **标准库限制**：核心不使用会抛异常或依赖 RTTI 的设施（`std::string`、`std::vector`、`std::function`、`std::iostream`、`std::any` 等）；使用自研的 arena/固定容量容器与非抛出辅助函数。
6. **测试与工具可例外**：测试框架自身可以启用异常/RTTI，但不得把该要求传播给库目标。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 默认开启异常 | 与嵌入式目标冲突；跨 ABI 风险；错误路径分散 |
| 提供异常开关 | 两套构建行为增加测试矩阵与语义分叉，已确认不采用 |
| 使用 C++14 | 主流工具链已支持 17；17 的结构化绑定/`if constexpr` 等更利于清理代码 |
| 依赖 STL 容器 | 分配失败会抛异常；无法满足无异常约束 |

## 后果

- 任何第三方依赖都必须满足“无异常/无 RTTI”；一期不引入第三方运行时依赖。
- 需要自研轻量容器与字符串视图；复杂度可控但需测试覆盖。
- 构建脚本固定注入禁用标志，CI 检查编译命令与二进制符号。
- 若未来工具链无法支持 C++17，需新 ADR，不得在实现中悄悄降级。
