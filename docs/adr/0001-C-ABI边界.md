# ADR-0001：C ABI 边界与向后兼容

- 状态：已确认（用户批准，2026-11-03）
- 日期：2026-11-03
- 关联：[C API 设计规范](../02-C-API规范.md)、[构建与移植](../06-构建与移植.md)、[ADR-0008](0008-基线决策汇总.md)

## 背景

外部集成方可能使用 C、C++、C#、Java（JNI）、Python（ctypes）等语言。库内部必须使用 C++ 实现，但不能把 C++ ABI、STL 类型、模板、异常或 RTTI 泄漏到边界。集成方还要求跨版本升级时不重新编译调用方代码。

## 决策

1. 公共接口只暴露 C ABI：C99 头文件、`extern "C"`、不透明句柄（`asnber_ctx_t`、`asnber_doc_t`、`asnber_node_t`）。
2. 所有公共符号统一 `asnber_` 前缀，只导出 `ASNBER_API` 标记的符号；内部 C++ 符号隐藏。
3. 公共结构体首字段为 `size_t struct_size`，并保留置零字段；新增能力通过新函数或结构体尾部字段实现。
4. **承诺向后兼容**：公共头文件只增不改，不删除/改签名、不改变既有枚举值与错误码语义；破坏性变更只能通过主版本升级并明确公告。
5. 提供版本宏（`ASNBER_VERSION_MAJOR/MINOR/PATCH`）与运行时查询函数；版本宏由 CMake 生成，与运行时版本、CMake 项目版本一致（详见 [ADR-0010](0010-版本一致性机制.md)）。
6. 不导出 C++ 符号、模板实例、RTTI 元数据；共享库不要求调用方使用 C++。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 直接暴露 C++ 类与 STL 类型 | ABI 随编译器/标准库变化；异常跨边界不可控；嵌入式不可用 |
| 扁平 C 结构体暴露内部布局 | 无法演进；调用方可写内部字段；破坏不变量 |
| 每个版本重新编译调用方 | 与向后兼容承诺冲突；集成成本高 |

## 后果

- 内部对象必须通过不透明指针与访问函数操作，不能直接暴露成员。
- 所有新增字段/函数必须评估对既有结构体大小与符号表的影响。
- 需要 ABI 检查（符号表、结构体尺寸、头文件差异）纳入 CI。
- 公共头文件已全部填充实现声明；当前 ABI 检查覆盖导出符号表（基线 `abi/*.symbols.txt`，`scripts/check_exports.py` 在 CI 比对）与描述表字节基线（`scripts/refactor_baseline.py --strict`）；结构体尺寸与头文件差异尚未单独设检查。
- 公共 ABI 新增 ANY 构树入口 `asnber_node_create_any`（`asnber/asnber_build.h`），属纯增量：只新增符号，不改既有函数签名、结构体布局或错误码语义。

被否决的“0.x 不承诺 ABI 稳定”策略不再采用：从基线起即按向后兼容目标设计，破坏性修改需主版本。
