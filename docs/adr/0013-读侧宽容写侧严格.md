# ADR-0013：读侧宽容、写侧严格

- 状态：已确认（用户批准，2026-11-09）
- 日期：2026-11-09
- 关联：[ADR-0012](0012-标准模块路线与只读边界.md)、[C API 规范](../02-C-API规范.md)、[CMS 模块 API](../02c-模块API-cms.md)、[能力范围](../03-ASN1能力范围.md)、[测试与验证](../07-测试与验证.md)

## 背景

标准模块的读侧（`*_open` + 只读访问器）与写侧（builder + `encode`）面对的是两类不同输入：

- 读侧输入来自外部：可能是 OpenSSL、其他工具或历史系统产出的 BER/DER，可能有可选字段缺失、未知扩展字段、与结构定义不完全匹配的标签、超出 RFC 规定范围的 `version` 值，甚至字段配对不合规（如 `AuthenticatedData` 的 `authAttrs` 与 `digestAlgorithm` 只出现一个）。
- 写侧输入来自调用方：由本库组装的字节要交给其他实现解析，必须只产出库里能担保的结构。

实现中读侧统一只设 `ASNBER_DECODE_COPY_INPUT`，不启用 `ASNBER_DECODE_STRICT_SCHEMA`；写侧在 `encode` 阶段校验版本配对、属性集合非空等规则。这一差异此前散落在各头文件与文档措辞里，容易被读成「实现还没做完」，因此需要固定为设计选择。

## 决策

### 1. 读侧只做结构投影，不做语义校验

- 不校验证书链、不做信任判断；不校验 MAC、不算摘要、不解密、不做密钥派生。
- 不校验版本语义：`version` 原样返回，RFC 规定的取值集合（如 CompressedData 必须为 0、AuthenticatedData 为 0/1/3）由调用方自行断言。
- 不校验字段配对：`authAttrs` 与 `digestAlgorithm` 任一方向缺失都照常打开并投影。
- 不校验算法参数：`parameters` 只作为原始 TLV 返回，不展开、不判断与算法 OID 是否匹配。

### 2. 读侧对未知与不合规编码宽容

- 不启用 `ASNBER_DECODE_STRICT_SCHEMA`：与任何字段都不匹配的标签按未知字段静默忽略，不影响其余字段投影。
- 根 `SEQUENCE` 之后的尾随数据仍然返回 `ASNBER_E_TRAILING_DATA`——宽容有边界，不多吃字节。
- 构造形式（不定长、构造 OCTET STRING 分段）按核心既有 BER 合并规则展平，不因非 DER 形态拒绝。

### 3. 写侧只产出可担保的子集

- 版本与可选字段的配对在 `encode` 阶段校验（如非 0 版本必须提供 `originatorInfo`、`digestAlgorithm` 与 `authAttrs` 必须成对出现）。
- 描述表约束在写侧生效：空 `SET`（`SET SIZE (1..MAX)`）返回 `ASNBER_E_INVALID_VALUE`，不生成非法结构。
- 写侧不做隐式修补：不补默认值、不排序调用方给的内容字节、不重排属性集合（`signedAttrs` 只改外层标签，长度与内容逐字节不变）。

### 4. 宽容读的边界写入契约

每个模块的公共头文件与 `docs/02*` 必须写明本 ADR 第 1、2 条对应的具体行为，措辞与实现严格一致；新增读侧容忍行为或收紧写侧校验时先改契约再改实现。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 读侧默认启用 `ASNBER_DECODE_STRICT_SCHEMA` | 真实输入的未知字段、历史编码会被一律拒绝，模块失去「读出结构再判断」的用途；严格模式仍可由调用方在核心层显式启用 |
| 读侧顺带做语义校验（MAC、版本、配对、证书链） | 需要密码学实现与信任模型，超出 ASN.1 库定位，且把「结构可解析」与「内容可信」混为一谈，容易被误用为安全结论 |
| 读侧静默规范化（重排、补默认值、去重） | 改变调用方拿到的字节，掩盖输入问题；往返逐字节一致这一条可验证性质也会失效 |
| 写侧放宽到「调用方给什么写什么」 | 会产出本库自己都读不回来的结构，且把非法编码的责任外推给下游解析器 |

## 后果

- 调用方必须自行完成语义判断：版本范围、属性配对、MAC/签名校验、证书链与信任决策。文档与头文件已按此描述，不得暗示库已完成这些校验。
- 差分与往返测试的判据是「结构一致 + 往返逐字节一致」，不是「语义合法」；fuzz 语料可以包含宽容读接受的非常规输入。
- 读侧宽容意味着同一份字节可能被多个不同结构同时接受，调用方需按实际 content type 选择入口。
- 读侧一旦收紧（例如未来引入严格模式开关），属于契约变更，必须同步头文件、`docs/02*`、CHANGELOG 与本 ADR。
