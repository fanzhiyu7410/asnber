# ADR-0006：测试技术栈

- 状态：已确认（修订，2026-11-19）
- 日期：2026-11-03；修订 2026-11-19
- 关联：[测试与验证策略](../07-测试与验证.md)、[构建与移植](../06-构建与移植.md)、[ADR-0008](0008-基线决策汇总.md)（D10）

## 背景

测试需要：轻量、可离线构建、贴近库的无异常约束、易与 CTest 集成。早期选型曾倾向 vendored doctest；实现期实际以无第三方依赖的最小 C 断言完成全量用例，再引入框架收益有限、会增加仓库与许可证登记负担。

## 决策

1. **单元 / 模块 / 往返测试断言：`tests/support/check.h`**（仓库自有、无第三方依赖）+ **CTest** 注册。
2. **C ABI 测试**用 C99 编写，直接包含公共头文件并链接库，验证 C 语言可见性与生命周期。
3. **模糊测试：libFuzzer**（Clang），harness 在 `tests/fuzz/`；由编译器工具链提供，不进入仓库、不随产物分发。
4. **内存/UB 检查**：ASan + UBSan 为主；Valgrind、DrMemory 作为平台补充。
5. **互操作 / 差分**：OpenSSL `asn1parse`、Python `asn1tools` 作为外部参照；差分在本地与 `ci.yml` 的 baseline 路径使用，不作为构建依赖。
6. 测试目标不得改变库目标的编译选项（库仍禁用异常与 RTTI）。
7. **不引入 doctest**（或同类第三方测试框架），除非后续有明确的参数化/过滤等刚需并先修订本 ADR 与依赖清单。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| GoogleTest | 体积/编译成本高；与无异常目标不完全贴合 |
| Catch2 | 单头模式较重；引入第三方 |
| doctest（原 D10 取向） | 实现期 `check.h` 已覆盖全量 CTest；vendor 增加依赖登记与迁移成本，无增量能力刚需 |
| 只做 fuzz 不做单元测试 | 难以定位语义与错误码问题 |

## 后果

- 测试栈零第三方源码；清单仅登记工具链提供的 libFuzzer（若扫描到 `-fsanitize=fuzzer`）。
- D10 中「测试框架 doctest」由本修订取代；C++17 基线不变。
- 文档、`THIRD_PARTY_NOTICES.md`、依赖清单与 `tests/CMakeLists.txt` 注释与本决策对齐。
