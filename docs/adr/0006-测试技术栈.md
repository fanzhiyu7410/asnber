# ADR-0006：测试技术栈

- 状态：已确认（用户批准，2026-11-03）
- 日期：2026-11-03
- 关联：[测试与验证策略](../07-测试与验证.md)、[构建与移植](../06-构建与移植.md)

## 背景

测试需要：轻量、可离线构建、C++17、能在无异常环境下工作、易与 CTest 集成。GoogleTest 功能强但体量大、编译慢，且依赖异常/死亡测试等机制；库本身禁用异常与 RTTI，测试栈应尽量贴近该约束。

## 决策

1. **单元测试框架：doctest**（单头文件，vendored 固定版本，避免网络依赖）。
2. **测试注册：CTest**；每个测试可执行文件注册为一个或多个用例。
3. **C ABI 测试**用 C99 编写，直接包含公共头文件并链接库，验证 C 语言可见性与生命周期。
4. **模糊测试：libFuzzer**（clang），harness 放在 `tests/fuzz/`；AFL++ 作为可选替代，不作为基线。
5. **内存/UB 检查**：ASan + UBSan 为主；Valgrind、DrMemory 作为平台补充。
6. **互操作**：OpenSSL `asn1parse`、Python `asn1tools` 作为外部参照，仅在 `interop` CI job 中启用，不作为构建依赖。
7. 测试目标可以启用异常/RTTI，但不得改变库目标的编译选项；若 doctest 在无异常配置下运行，使用 `DOCTEST_CONFIG_NO_EXCEPTIONS`。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| GoogleTest | 体积/编译成本高；死亡测试依赖平台特性；与无异常目标不完全贴合 |
| Catch2 | 单头模式较重；编译时间高于 doctest |
| 自研断言框架 | 维护成本高，缺少参数化/过滤等基础能力 |
| 只做 fuzz 不做单元测试 | 难以定位语义与错误码问题 |

## 后果

- 仓库需要 vendored doctest 头文件；许可证需与 MIT 兼容（doctest 为 MIT）。
- 测试矩阵需覆盖“库无异常 + 测试可异常”的组合，确保库目标未被污染。
- 互操作测试可能因外部工具版本产生噪声；差异必须有归档与解释。
