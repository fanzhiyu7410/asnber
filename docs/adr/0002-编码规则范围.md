# ADR-0002：编码规则与输入方式分期

- 状态：已确认（修订，2026-11-03）
- 日期：2026-11-03
- 修订：按“通用核心 + 独立标准模块”的分层收敛 CER 与 PER/UPER 的排期，见 [ADR-0009](0009-分层与独立模块策略.md)
- 关联：[ASN.1 能力范围](../03-ASN1能力范围.md)、[里程碑](../09-里程碑与分期.md)、[ADR-0009](0009-分层与独立模块策略.md)

## 背景

BER/DER 是证书、CMS、LDAP 等领域的基础，需求确定；CER 与 PER/UPER 的实现成本与依赖差异很大。输入来源既有完整缓冲，也有流式网络/文件数据。若一期同时铺开所有规则与增量接口，会拖慢可用版本并放大风险。

## 决策

1. **一期只做 BER 与 DER**：
   - BER 解码：确定长度 + 不定长 + 高标签号。
   - DER 解码：严格模式。
   - DER 编码：规范化输出；DER 是 BER 的合法子集，因此不单独提供 BER 编码。
2. **CER 改为需求触发**：不列入二期固定范围。只有当出现明确使用 CER 的场景时，才在依赖 DER 基础、不定长处理与字符串分块规则后评估。
3. **PER/UPER 暂不规划**，也不列入任何固定阶段。理由：证书/PKCS 生态统一使用 DER；PER 依赖 schema 推导的位置编码与约束求值，本场景不出现。仅当出现明确需求（如 5G/智能卡项目）时重新评估，重启前必须更新本 ADR 与 [ADR-0009](0009-分层与独立模块策略.md)。
   - 若重启，仍必须等待以下依赖可用：模式/约束求值（SIZE、值域、可扩展性）、定长计算（固定部分、OPTIONAL 位图、CHOICE 索引）、可选字段存在性与默认值判定。
   - 没有模式描述时不做 PER/UPER 的“尽力猜测”实现。
4. **输入方式**：
   - 一期支持整块 buffer 与回调式数据源（reader），二者都物化完整 DOM。
   - 增量 feed 接口放二期；事件式/SAX 在二期评估，不在一期承诺。

## 备选方案

| 方案 | 否决理由 |
| --- | --- |
| 一期同时做 CER/PER/UPER | PER 强依赖模式与约束；会阻塞可用版本 |
| 把 CER 固定放二期、PER/UPER 固定放后期 | 证书/PKCS 场景不使用 PER，固定排期会制造无目标工作量 |
| 只做 DER，不支持 BER 解码 | 大量现实输入（CMS 等）使用 BER 不定长，能力不足 |
| 一期就做增量 feed | 状态机复杂度高，且与一次性 DOM 的所有权/错误语义冲突 |
| 单独提供 BER 编码器 | DER 输出已可被 BER 消费方接受；额外编码路径增加测试面 |

## 后果

- 文档必须明确“DER 输出即合法 BER”，避免用户误以为缺少 BER 编码是缺陷。
- CER 与 PER/UPER 不得出现在一期/二期承诺中；PER/UPER 的依赖条件需保留在文档中，供重启评估。
- reader 接口只解决输入来源，不承诺增量解析；二期新增接口需保持与一期语义一致。
