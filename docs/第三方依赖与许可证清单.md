# 第三方依赖与许可证清单

本清单是项目第三方依赖的**唯一登记入口**。任何新增依赖必须先在本清单登记并通过许可证审核，再进入代码；CI 使用 [scripts/check_third_party.py](../scripts/check_third_party.py) 比对清单与实际引用，发现未登记依赖即失败。

## 1. 策略

1. **运行库零第三方依赖**：核心 `asnber` 与 `asnber-pkix`、`asnber-cms`、`asnber-pkcs1/8/10/12`、`asnber-pkcs` 的发版产物（shared/static）不得链接任何第三方库，仅允许 C 运行库与平台系统库。
2. **测试与工具依赖限定宽松许可**：仅接受 MIT、BSD-2-Clause、BSD-3-Clause、Apache-2.0（含 LLVM 例外）等宽松许可；禁止 GPL/LGPL/AGPL 或许可不明代码进入仓库。
3. **逐项登记**：每个依赖记录名称、版本、用途、引入阶段、许可证、来源链接、是否随产物分发。
4. **分发合规**：项目自身保持 MIT；发版时随包提供 `THIRD_PARTY_NOTICES.md`；README 声明依赖状态。

## 2. 登记字段

| 字段 | 要求 |
| --- | --- |
| 名称 | 依赖的通用名称，与源码/构建中的引用名称一致 |
| 版本 | 固定版本或版本范围；随工具链提供的写明“随编译器工具链” |
| 用途 | 测试框架、模糊测试驱动、工具库等；不得用于运行库 |
| 引入阶段 | 一期、二期或具体里程碑 |
| 许可证 | SPDX 标识或完整名称；多种许可时写清适用项 |
| 来源 | 官方仓库或文档链接 |
| 随产物分发 | `是` / `否`；运行库依赖必须为 `否` |

## 5. 变更流程

1. 在引入依赖的代码或构建变更**之前**，先更新本清单。
2. 确认许可证属于允许范围；GPL/LGPL/AGPL 或许可不明一律拒绝。
3. 若依赖随产物分发，同步更新 `THIRD_PARTY_NOTICES.md`；运行库依赖不允许随产物分发。
4. 运行 `python scripts/check_third_party.py`，未登记引用必须为零。
5. 评审时同时检查清单、`THIRD_PARTY_NOTICES.md` 与实际引用三者一致。

## 6. 检查脚本

```bash
python scripts/check_third_party.py            # 在仓库根目录运行
python scripts/check_third_party.py --list     # 只列出已登记依赖
```

脚本扫描 `include <...>`、CMake `FetchContent_Declare` / `find_package`、`third_party/` 等 vendored 目录以及 `-fsanitize=fuzzer` 引用，与清单比对。退出码：`0` 通过，`1` 发现未登记依赖或许可证违规，`2` 清单格式错误。
